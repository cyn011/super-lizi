## 2. Ch3 叙事弧与 3-1 的 opener 定位

**段 1 · 跃出**：2-6《熔心终焉》的「出渊之门」并非归途——栗宝跃出的那一刻，火山口的上升热柱把它整个托了起来。脚下的熔金迅速缩成一点橙光，气压骤降，第二章那种「向下、向暗、向热」的重量第一次从身上卸掉。

**段 2 · 第一口空气**：它睁开眼，落进一片从未见过的地方：脚下不是岩，是**厚得能站人的云海**；头顶不是穹顶，是**墨色的星空**；四周悬着一座座**苍白发亮的浮岩**。这里冷、静、亮——与深渊的暗、闷、热正好翻面。这是新维度的第一口空气。

**段 3 · 芽张开了**：也是在这一刻，栗宝头顶那枚从 1-1 就带着的**嫩芽**，被稀薄的气流吹得张开成一对薄翼——它第一次发现自己能**慢下来**。Ch3 的核心动词由此确立：不是「跳得更高」，而是「**停得更久**」。

**段 4 · Ch3 走向**：第三章将围绕「滞空」把整片星界拆开——3-1 教会羽降、后续关卡把浮岛拉得更远、把星隙叠得更立体，直至章末重新面对「为什么要往上」。

### 2.1 3-1 的 opener 三重定位（MDA · 动词优先）

| 定位 | 内容 | MDA 映射 |
|---|---|---|
| **教学（primary）** | 用 5 段曲线把「长按跳跃 = 羽降」从 0 教到 mastered（§4.5） | M：新增 glide 机制；D：滞空—暴露权衡；A：Sensation（新触感）+ Discovery |
| **过渡（secondary）** | 从 2-6 的「密度高压」回落到 opener 的松弛密度（11 敌 vs 2-6 的 16 敌），给认知让位给新机制 | 心流：难度降档 + 技能新增 = 通道内平移，不掉出 |
| **基调奠定（tertiary）** | 明度翻面（暗天亮地）+ 敌阵稀疏 + 长滞空 → Ch3 = 「轻、冷、开阔」，与 Ch2「重、热、逼仄」对立 | A：Fantasy / Expression |

> **动词优先**：Ch1 的动词是「跑·跳·踩·扔」，Ch2 是「闯·避·抗」，**Ch3 的新动词是「浮」**。3-1 的全部设计只服务这一个动词。

## 3. 新维度 biome 主题键建议

### 3.1 主题键：推荐 `astral`（星界）

| 候选键 | 语义 | 与现有 12 键的冲突审查 | 结论 |
|---|---|---|---|
| `sky` | 天空 | ⚠️ 与已 live 的 **`storm_sky`** 概念重叠（storm_sky 已是「蓝紫风暴 + 浮岛」），玩家会读成「2-3 的换皮」 | ❌ 撞概念 |
| `floating` | 浮岛 | 语义泛，且浮岛形态已被 storm_sky 占用为装饰语言 | ❌ 撞概念 |
| **`astral`** | **星界** | 与 12 键全异；「星空 + 苍白浮岩」是全项目未出现的概念 | ✅ **主推** |
| `aether`（备选） | 以太 | 全异，但中文语感弱于「星界」 | ★★ 备选 |

> **`astral` 与 `storm_sky` 的硬区分（三重）**：① **天空明度反向**——storm_sky 是「冷蓝阴天」（`bg=#4A78C0`，中明度），astral 是「墨色星空」（极暗）；② **地面明度反向**——storm_sky 地面 `rockFace=#6E7BF2` 中明度蓝紫，astral 是**苍白**浮岩（高明度，全 biome 唯一）；③ **情绪反向**——storm_sky 压抑/有威胁，astral 澄澈/无威胁。

### 3.2 锁内 11 色如何做出「从未见过」——明度翻面 + 形状反转（0 新增 hex）

**核心洞察（跨 12 biome 明度审计）**：现有 12 个 biome 的 `rockFace`（地面主面）全部落在**中—暗**明度带：

| biome | rockFace | 明度带 |
|---|---|---|
| volcano | `#2A1A12` | 近黑 |
| silhouette | `#254060` / street `#304E7D` | 暗 |
| grass | `#3A2A1F` | 暗 |
| cave / mountain / sea / office | `#4A78C0` | 中 |
| storm_sky | `#6E7BF2` | 中 |
| vine_forest | `#7CC242` | 中 |
| desert / home | `#F2933C` | 中高 |

> **12 个 biome 里没有一个用过「高明度地面」。** 这就是 0 新增 hex 条件下唯一还没被用掉的**维度**——不是色相，是**明度**。

**astral 的做法 = 把明度关系整体翻面**：

| 手法 | volcano（Ch2 终章，对照） | **astral（Ch3 开篇）** | 观感效果 |
|---|---|---|---|
| 天空 | 暗紫 `#3F45A8`（中暗） | **墨蓝星空 `#1F2244`**（`darken(#6E7BF2,0.72)`，全 biome 最暗天） | 更深的「外太空」 |
| 地面 | 玄武岩黑 `#2A1A12`（近黑） | **星白浮岩 `#BEC4F9`**（`lighten(#6E7BF2,0.55)`，**全 biome 唯一高明度地面**） | 「地比天亮」——视觉直觉反转 |
| 可站立信号 | 黑岩 + **亮**顶缘发光边 | 白岩 + **暗**顶缘边（`#6E7BF2`） | **发光边反转**，同一套语言、相反读法 |
| 明度对比 | 亮元素浮在暗底 | 暗元素刻在亮底 | 前景/背景关系整体倒置 |

- **形状语言（不新增 hex，只换轮廓）**：地形从「连绵地壳」改为**离散菱形浮岩块**（底面收窄成倒棱台，强调「悬空」）；装饰 `deco_star`（点状星屑）、`deco_nebula`（低 alpha 星云带）、`deco_dust`（缓升尘）——全部是**点/带**语言，区别于 cave 的柱状、volcano 的裂隙、vine 的藤蔓、sea 的波纹。
- **概念不撞**：星屑/星云/苍白浮岩，与已有 12 biome 的「岩/藤/浪/沙/家具/楼宇/办公/剪影/熔岩」形态无一重合。

## 4. 新机制提案（核心）

### 4.1 三候选评审

> 已排除用户候选 ③弹射（`bouncy_vine` 已 live）、④风场（`cyclone` 已 live）——见 §0。

| 维度 | ① 浮岛漂移（移动平台） | **② 羽降（滑翔/缓降）** | ⑤ 重力翻转 |
|---|---|---|---|
| **一句话定义** | 部分浮岛沿固定轨迹匀速往返，玩家站上后随之位移 | 空中下落时**持续按住跳跃**，头顶嫩芽张开成薄翼，下落速度被钳制到低值，滞空时间大幅延长 | 触发后整关重力方向翻转，天花板变地面 |
| **教学价值** | 中——「等时机上车」是老平台跳跃词汇，玩家已会，新鲜感来自视觉而非认知 | **高**——引入全新动词「浮」，且**可被金币弧无文字教学**（面包屑引导，见 §4.5）；Ch3 后续可持续加压 | 高但**破坏性**——需重学全部空间直觉，Ch3 开篇即重置玩家肌肉记忆 |
| **与现有跳跃手感耦合度** | **低耦合（=弱）**——不改变跳跃本身，只改变落点是否在动。跳跃手感原封不动，机制像「外挂在地形上」 | **高耦合（=强）**——直接长在跳跃动词上：`jumpHeld` 复用现有输入，与二段跳（按下沿）、短跳（松开沿）三者共用一个键但**互不冲突**（见 §4.3），形成「点—点—按住」的连续技 | **冲突**——`stompBounce`/`coyote`/`jumpBuffer` 全部需镜像分支，手感被改写 |
| **实现粗略成本** | **中高**——`body.ts:90` 的 `registerMovingPlatform` 是从未接线的 stub；需补：随动携带（carry）、与 oneway 的交互、挤压（crush）判定、检查点重生时的平台相位复位、headless 可测性。移动实体碰撞是平台跳跃里 bug 密度最高的一类 | **低**——`InputState.jumpHeld` 已有（零新输入）；`physics-config.maxFall:900` 已是全局钳制点，羽降=**条件性替换该钳制值**；角色控制器「只设 vx/vy」的铁律天然兼容；纯函数、可 headless 单测 | **高**——重力符号、相机、敌人 AI 的 up/down 语义、渲染翻转、UI 全线波及 |
| **心流 / 公平风险** | 中——移动平台失败常导致「等下一趟」的**空转等待**，是心流杀手；且与已 live 的节拍平台（周期性显隐）**认知功能重叠**，两套「等相位」机制叠加 = 认知过载 | **低（且可控）**——失败代价可设计为 0（落回云海地面，无伤害、无扣命）；主导策略风险已被三重成本对冲（§4.6） | **高**——晕动风险、可访问性风险（Reduce Motion 无法缓解方向感丧失） |
| **叙事契合（浮岛/天空/星界）** | 中 | **高**——「第一口空气」的字面机制化：空气本身成为可用资源；且复用栗宝头顶嫩芽（1-1 就有的 IP 特征）作为翼，零新角色资产 | 中 |

### 4.2 推荐：**② 羽降（Feather Descent / `glide`）**

**推荐理由（三条，按权重）**
1. **它是唯一「长在既有动词上」的机制**。移动平台改的是地形，重力翻转改的是世界；只有羽降改的是**栗宝自己**——Ch3 是「栗宝获得新能力」的章，不是「地形变花样」的章。这与「嫩芽张开」的叙事是同一件事。
2. **实现成本与新鲜度的比值最优**。零新输入信号、零新实体类型、零新 tile kind、零敌人改动；工程量集中在角色控制器的一处条件钳制 + 一份配置（§4.7）。对 Ch3 开篇而言，这是「用最小引擎风险换最大玩法增量」。
3. **它自带反向教学**。羽降延长滞空 = 延长暴露在 `shi_pao` 弹幕下的时间，所以「会用」之后还要学「何时不用」。一个机制吃两层教学，撑得起整章。

### 4.3 与现有输入 / 手感的耦合契约（无冲突证明）

跳跃键（`INPUT_JUMP`）现已承载三种语义，羽降是第四种，四者靠**边沿类型 + 状态**天然正交：

| 语义 | 触发条件 | 现状 |
|---|---|---|
| 起跳 | `jumpPressed`（按下沿）+ grounded/coyote | 已有 |
| 二段跳 | `jumpPressed`（按下沿）+ `airJumpsLeft>0` | 已有 |
| 短跳截断 | `jumpReleased`（松开沿）+ 上升段 + 未截断过 | 已有（`shortHopCut:0.7`） |
| **羽降** | **`jumpHeld`（持续态）+ `!grounded` + `vy > activateVy`（仅下落段）** | **新增** |

- 羽降**只在下落段生效**（`vy > 60`），因此**绝不影响**上升段的短跳手感——短跳发生在松开沿，羽降发生在下落中的持续按住，时序不重叠。
- 玩家若「起跳后一直按住不放」→ 得到满跳 + 羽降，但**放弃二段跳**（二段跳需新的按下沿）。这是一个**真实的取舍**，构成技巧表达（`点—点—按住` 是最优连续技），而非无脑最优。
- 羽降**不提供水平推力**，水平速度仍受 `moveSpeed:140` 约束——它只买「时间」，不买「速度」。

### 4.4 数值建议与射程推算（⚙️ 数值交 engineering-lead / QA 调校）

| 参数 | 建议值 | 单位 | 说明 |
|---|---|---|---|
| `glide.fallMax` | **140** | px/s | 羽降时的下落速度上限（替代全局 `maxFall:900`）。取 = `moveSpeed:140` → 轨迹恰为 **45° 斜降**，玩家凭直觉即可预判落点（可读性设计） |
| `glide.activateVy` | **60** | px/s | 仅当 `vy >` 此值（已在下落）才激活，保护上升手感 |
| `glide.maxMs` | **0** | ms | 0 = 不限时。3-1 不设资源条（opener 不引入第二套认知）；若 QA 认为过强，改为 1200ms 即可（回退方案，§4.8） |
| `glide.horizontalScale` | **1.0** | — | 羽降中水平加速/最大速度不变（不做「滑翔加速」，防主导策略） |

**射程推算（基于现有配置，供关卡布局校验）**

- 满跳顶点高度 `h₁ = 480² / (2×1800) = 64px`（2 格）
- 二段跳（`0.93×480 = 446`）于顶点续跳，追加 `446² / (2×1800) ≈ 55px` → 总顶点约 **119px**（3.7 格）
- **无羽降**：同高平台间最大水平跨越 ≈ `140 × 0.878s ≈ 123px` ≈ **3.8 格**（实战安全值取 **3.5 格**）
- **有羽降**：下落段由 `0.363s` 拉长到 `119/140 = 0.850s`（+0.487s）→ 总滞空 ≈ `1.365s` → 水平 ≈ `191px` ≈ **6.0 格**（实战安全值取 **5.0 格**）

> **关卡设计门槛由此确定**：`gap ≤ 3 格` = 人人可过；`gap = 5 格` = **必须羽降**（且留 1 格容错余量）；`gap ≥ 7 格` = 不可过（本关不使用）。§5 的浮岛间距严格按此表布置。

### 4.6 与四敌的协同（**只改变空间，不改变敌语义**）

> 红线：`gu_bao`/`ci_li`/`du_fu`/`shi_pao` 的 AI、判定盒、可踩性、伤害语义**一律不动**，本关不新增任何敌人代码。羽降改变的是「玩家与敌人的**相对空间关系**」。

### 4.8 降级 / 心流回退方案（三级，逐级更保守）

## 10. `parTimeMs` 可达档建议

**建议初值：`parTimeMs = 88000`（QA 调校区间 84000–95000）**

**推导过程**

1. **章节速率基线**：2-1(w44)=72000 → 1636 ms/格；2-2(w46)=76000 → 1652；2-3(w46)=78000 → 1696；2-4(w46)=80000 → 1739；2-5(w48)=84000 → 1750；2-6(w56)=100000 → 1786。世界 2 基线 ≈ **1700–1790 ms/格**。
2. **长度基准**：3-1 width46 × 1750 ≈ **80500**（与同宽的 2-4 的 80000 一致）。
3. **新机制学习溢价 +10%**：这是本关与 2-4 的**唯一实质差异**。溢价来源三项——① 羽降轨迹需试错才能预判落点（S1/S2 反复尝试）；② 羽降本身**主动放慢下落**，同样路径的通过耗时天然更长（`fallMax 140` vs 自由落体，单次长滞空约多 0.5s，全关约 8–12 次 → +4~6s）；③ 高路探索（seed_01/05、金币弧）诱导玩家绕路。→ `80500 × 1.10 ≈ 88550` → 取整 **88000**。
4. **对照上下文**：1-1(w40, 教学关)=26000 / 1-7(w54)=52000 是**世界 1 的紧凑档**；世界 2 起 par 显著放宽。88000 落在「比同宽 2-4 宽 10%、比 2-6 climax 紧 12%」的位置，符合「Ch3 开篇 + 新机制」的双重身份。
5. **语义提醒**：`parTimeMs` 是**时间评级达标门槛**而非速通极限（`result-screen.ts` 二元门槛，`elapsedMs ≤ parTimeMs` 即满足），故取慷慨值。**若 §4.8 的 L1 回退（收紧 `fallMax`）生效，par 可回收至 84000。**
