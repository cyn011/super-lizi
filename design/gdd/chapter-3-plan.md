## 1. Ch3 总关数与结构：**6 关，x = 6，3-6 为 climax**

### 1.1 结论与理由

| 理由 | 说明 |
|---|---|
| **① 与 Ch2 同构，节奏可预期** | Ch1=7 关（7 个 biome 的「旅行章」，par 650–963 ms/格，短平快教学世界）；Ch2=6 关（下沉章）。Ch3 与 Ch2 同为「单一情绪弧 + 一个终章」的世界，取 **6** 与 Ch2 对齐，玩家对章长已有预期 |
| **② 一个机制的完整 mastery 弧恰好需要 5 关** | glide 有 **4 条可深化轴**（空间射程 / 时间相位 / 代价与精度 / 链式连续技，见 §3.2）。3-1 教学 + 4 关各吃透 1 轴 + 1 关 gauntlet 混编 = **1+4+1 = 6**。7 关会出现「第 5 轴无内容可填」→ 重复关；5 关则必须两轴挤一关 → 认知过载 |
| **③ 制作节奏** | 6 关 = 3 批 × 2 关（§8），每批可独立出包验收，符合「避免一关一关反复出包」的诉求 |
| **④ 终章必须能超过 2-6** | 3-6 取 w56 / 敌18 / cp5 / par114000，在长度持平、密度（0.321 vs 0.286）与检查点（5 vs 4）上**超过** 2-6，章末量级成立 |

## 2. 逐关简报（3-2 ~ 3-6）

> 每关一段。坐标级细节（entities 数组、tiles 规则）留给**逐关简报**（批次启动时产出，体例同 `level-3-1-design.md`）；本节定义每关的**契约边界**，供批量实现直接展开。

### 2.1 3-2《星隙长渡》· 深化 A：空间

- **工作关名**：《星隙长渡》（备选：《碎岛远津》《云上长渡》）。「长渡」= 长距离横渡，呼应「初息」之后的第一次真正远行。
- **主题/变体**：`astral` **复用**（0 新 biome、0 新 hex、0 美术依赖）。视觉差异全部来自**构图**：浮岩由 3-1 的「零散阶梯」改为**两两成组的远岛群**，岛间留出画面级空隙（星隙），远景浮岛剪影密度调低 → 读感更空旷。
- **机制重心**：**长距离滑翔 + 落差射程预判**。核心教具 = §3.3 的「落差射程公式 `safe_gap ≈ 5 + Δdown`」：本关首次出现**降落式长渡**（起点 ty3 高栖岛 → 落点 ty5，Δdown=2 → 安全 7 格）。玩家学到「往下飘能飘更远」——这是 3-1 没教过的一维。同时首次出现 **升高跨越 ≤3 格红线**的反面示范：一处 ty5→ty4 的 3 格上跨，明确「羽降对上升无效」（`activateVy=60` 只在下落段生效）。
- **长度/难度**：`width=48`（同 2-5）；难度档 = 3-1 + 半档（**低-中**）。
- **敌阵**：12 敌 = `gu_bao`×3 / `ci_li`×3 / **`du_fu`×4** / `shi_pao`×2。du_fu 加到 4 是刻意的——**每一处「必需 glide」的长渡中段都放一只 du_fu 作第二解**（踩踏续跳），守 3-1 附录 A 的「无单一最优路线」。节奏段：S1 松（1 敌）→ S2 长渡区（2 敌，均为 du_fu 踏板）→ S3 地面压力回升（4 敌）→ S4 长渡+地面混合（4 敌）→ S5 收束（1 敌）。
- **检查点 3**（约每 11 格）；**种子 5**（4 颗地面主路，1 颗长渡终点岛 = 技能奖励）；**节拍 1 簇**（ty=4，仍为可选高路，不与长渡叠加）。
- **parTime**：**92000**（QA 区间 88000–98000；1917 ms/格）。
- **叙事节拍**：星界比想象中更**大**。栗宝试着往前飘，发现浮岩之间隔着看不见底的星隙——「这地方没有尽头吗？」第一次意识到「浮」不只是好玩，而是这个维度**通行的唯一方式**。ascend 弧此处 = **横向确认世界的尺度**（还没开始真正向上）。

### 2.2 3-3《鸣星回阶》· 深化 B：时间

- **工作关名**：《鸣星回阶》（备选：《叩律星阶》《环星律动》）。「回阶」= 循环出现的阶梯，直指节拍平台。
- **主题/变体**：`astral` **复用**。构图变体 = **纵向阶梯**（浮岩沿 ty5→ty4→ty3 排成上行梯列），远景星环光带加密 → 「这片星界有脉搏」。
- **机制重心**：**glide × 节拍相位**。这是 glide 的**时间维度**：3-1 只把节拍当「合流考核」，3-3 把它变成核心——**滞空 = 等待相位的工具**。典型装置：从高岛跃出 → 目标 beatPlatform（ty=4）此刻处于 ghost 态 → 玩家**用羽降把下落时间从 0.36s 拉到 0.85s**，恰好等到平台实体化再落。「浮」第一次不是为了走更远，而是为了**等**。
- **长度/难度**：`width=50`；难度档 = **中**（认知负荷峰在相位读取，不在密度）。
- **敌阵**：13 敌 = `gu_bao`×3 / `ci_li`×3 / `du_fu`×4 / `shi_pao`×3。节奏段刻意在节拍区**留白**（相位读取时不给弹幕，防认知过载）：S2/S4 的两处节拍簇附近 ≤1 敌，压力集中在 S3/S5 的地面段。
- **检查点 3**；**种子 6**（3 颗地面、2 颗节拍高路、1 颗梯顶）；**节拍 2 簇**（上限，2-6 先例；两簇均 ty=4，**同 bpm120 / grid8 / `SSGG`**，不引入新 pattern → 相位可迁移，防过载）。
- **parTime**：**96000**（区间 92000–102000；1920 ms/格）。相位等待天然吃时间，但仍守 Ch3 基线带。
- **叙事节拍**：星界有节律。浮岩不是死的——它们随某种看不见的脉搏明灭。栗宝跟着这个脉搏第一次**真正往上爬**了一层。ascend 弧此处 = **向上的第一步 + 世界不是空的（它在呼吸）**。

### 2.3 3-4《陨雨回廊》· 深化 C：代价

- **工作关名**：《陨雨回廊》（备选：《炮雨星廊》《流火长廊》）。刻意与 Ch2 的《剪影回廊》（2-4）**互文**——同为「回廊」，一暗一亮，一逼仄一开阔。
- **主题/变体**：`astral` **复用**。构图变体 = **狭长走廊**（浮岩变窄，多处仅 1-2 格宽的「窄岛」），前景星尘密度调高 → 压迫感。
- **机制重心**：**glide 作为负债 + 精确落点**。把 3-1 S4 的「反向教学」从 1 段扩写成**整关主题**：`shi_pao`×5（本章火力峰）在 y=100 织成横向弹道网，而羽降轨迹主带正是 y≈96~180 → **滞空越久，暴露越久**。同时窄岛（1 格宽）逼玩家把 45° 斜降轨迹**算准**——「不是不能飘，是只能飘刚刚好那么久」。这是 glide 从「资产」变成「需要克制的资源」的一关。
- **长度/难度**：`width=50`；难度档 = **中-高**（本关是全章第一个真正的「压力关」）。
- **敌阵**：14 敌 = `gu_bao`×3 / `ci_li`×3 / `du_fu`×3 / **`shi_pao`×5**。节奏段：S1 引导（1 敌）→ S2 单炮试探（2 敌）→ S3 双炮夹击 + 窄岛（4 敌）→ **S4 三炮走廊（本关压力峰，5 敌）** → S5 收束（2 敌）。
- **检查点 4**（+1，且 **cp4 紧贴 S4 走廊入口**，最小化回溯挫败，同 3-1 cp3 手法）；**种子 6**（4 颗在**地面主路**——本关公平性补偿：不擅长弹幕的玩家仍可满蜕变）；**节拍 1 簇**（降回 1 簇，把认知带宽让给弹道读取）。
- **parTime**：**98000**（区间 94000–104000；1960 ms/格）。走廊需要停顿等弹道窗口，par 略放宽。
- **叙事节拍**：星界不欢迎它。第一次有东西**朝栗宝开火**。翅膀让它慢下来，慢下来就成了靶子——「原来这份轻盈是要付代价的」。ascend 弧此处 = **阻力出现，上升第一次有敌意**。

### 2.4 3-5《凌霄绝息》· 高压前奏：链式

- **工作关名**：《凌霄绝息》（备选：《危穹独渡》《薄气高天》）。**与 3-1《浮空初息》成对**：初息（第一口空气）↔ 绝息（最稀薄的一口）——章内首尾呼应，同 Ch2「终焉」的命名手法。
- **主题/变体**：`astral` **复用**。构图变体 = **三层浮岩塔**（ty5 / ty4 / ty3 三层堆叠）。
  > ⚠️ **引擎上限声明**：`height=9`、地面顶 ty7 → 可用空域仅 ty0~ty6，实战可站立层为 **ty5 / ty4 / ty3 三层**（ty3 顶距地面 4 格 = 128px，已接近满跳+二段跳顶点 119px 的极限）。**三层即物理上限，3-6 不得再加层**——这条约束必须写进逐关简报，防实现期误设 ty2。
- **机制重心**：**链式滞空连续技**。glide→踩 `du_fu`→再 glide→踩 `ci_li`→落塔顶，把 3-1 S3 的「羽降+踩踏」从一次组合扩成**一串**。`du_fu`×5（本章踏板峰，y=120 恰在羽降主带）是本关的骨架。玩家学到：**滞空可以被「续」**——每一次踩踏都重置下落段，羽降因此可以无限接力（受 `du_fu` 摆位约束）。这是 glide 的技巧天花板。
- **长度/难度**：`width=52`；难度档 = **高**（全章次高，仅次于 3-6）。
- **敌阵**：16 敌 = `gu_bao`×4 / `ci_li`×4 / **`du_fu`×5** / `shi_pao`×3。节奏段：S1（2 敌）→ S2 双段链（3 敌）→ S3 三段链 + 地面压力（4 敌）→ S4 塔攀（5 敌，du_fu 密集）→ S5 塔顶收束（2 敌）。
- **检查点 4**；**种子 6**（3 颗地面、3 颗分布在三层塔的每一层 = 技能梯度奖励）；**节拍 2 簇**（一簇作链条的中继站，一簇作塔顶入口）。
- **parTime**：**104000**（区间 98000–110000；2000 ms/格）。
- **叙事节拍**：越往上空气越薄，翅膀撑得越吃力。栗宝一次次借着光精灵（du_fu）往上蹬——它已经不满足于「飘」，它在**攀**。头顶的墨色星穹第一次看得清纹路了：那不是天，那是**一层壳**。ascend 弧此处 = **看见了顶，也看见了它是可以被穿透的**。

### 2.5 3-6《星穹终启》· climax（章末）

- **工作关名**：《星穹终启》（备选：《破穹之门》《穹顶新生》）。**与 2-6《熔心终焉》严格对位**：终焉（关上）↔ 终启（打开）；下沉的休止符 ↔ 上升的开启符。
- **主题/变体**：**默认 `astral` 复用**（A 方案，0 美术）；**可选 B 方案 = 新 biome `zenith`（破晓穹顶）**，详见 §6.3 与 §9 拍板项 ②。无论哪种，凯旋之门做**「破穹之门」视觉变体**（2-6「出渊之门」的对位；纯 Graphics + 锁内色，art-director 微调即可）。
- **机制重心**：**四轴混编 gauntlet**——空间（长渡）/ 时间（节拍相位）/ 代价（弹幕下的克制）/ 链式（连续技）各占一个节奏段，最后在 final gauntlet 里同时出现。**不引入任何第 5 轴、不引入第 2 机制**（§7）。
- **长度/难度**：`width=56`（持平 2-6，全项目并列最长）；难度档 = **全章最高**。
- **敌阵**：18 敌 = `gu_bao`×4 / `ci_li`×4 / `du_fu`×5 / `shi_pao`×5（密度 0.321 > 2-6 的 0.286 = **全项目密度峰**）。节奏段（沿用 2-6 的 4 段 + Ch3 的四轴映射）：

  | S1 回望 | 2..13 | 松弛开场 + 一次长渡（Δdown=2） | 空间 |
  | S2 律动 | 14..26 | 节拍簇 `bp_z1`（ty4）+ 相位等待 | 时间 |
  | S3 陨雨 | 27..38 | 三炮走廊 + 窄岛精确落点 | 代价 |
  | S4 攀塔 | 39..49 | 三层塔 + du_fu 链 + 节拍簇 `bp_z2`（ty4） | 链式 |
  | **S5 final gauntlet** | 50..55 | cp5 之后：四轴同屏（长渡→炮口下的窄岛→链式续跳→破穹之门） | **混编** |

## 3. Ch3 难度 / 学习曲线

### 3.1 章级曲线形状（心流通道）

```
技能           3-1教学 ──→ 3-2空间 ──→ 3-3时间 ──→ 3-4代价 ──→ 3-5链式 ──→ 3-6混编
挑战(密度)     0.239       0.250       0.260       0.280       0.308       0.321
认知负荷       ★★★(新机制)  ★☆        ★★(相位)     ★★★(弹道)    ★★(已学)     ★★★(混编)
情绪           发现·松弛    开阔·远行   律动·上行    压迫·克制    攀登·吃力    爆发·突破
```

- **挑战单调上升、技能同步上升** → 心流通道内平移，无「掉出通道」的跳变。
- **认知负荷刻意起伏**（3-2 与 3-5 是负荷谷）——连续三关高负荷会疲劳；3-2 的「只学一条射程公式」和 3-5 的「用已学技能做长链」是**恢复关**，把带宽留给 3-3/3-4/3-6 的峰。
- 与 Ch1/Ch2 的关系：Ch3 par 基线（1900–2050 ms/格）高于 Ch2（1700–1790），**不是变难，是变慢**——羽降主动放慢下落 + 高路探索占比提升，这是章节手感的固有属性，须在 QA 沟通中说明，避免被读成「关卡拖沓」。

### 3.2 glide 的四条深化轴（一关一轴，无重复）

| 轴 | 关 | 一句话 | 反面（防主导策略） |
|---|---|---|---|
| **① 空间** | 3-2 | 往下飘能飘更远（`safe_gap ≈ 5+Δdown`） | 上升跨越羽降**零帮助**（≤3 格红线） |
| **② 时间** | 3-3 | 滞空是等待相位的工具 | 等太久 = par 压力；ghost 态误判 = 落回地面 |
| **③ 代价** | 3-4 | 滞空 = 暴露；窄岛 = 落点必须算准 | 弹道网下**快速下落反而更安全** |
| **④ 链式** | 3-5 | 踩踏重置下落段 → 滞空可接力 | 链条依赖 du_fu 摆位，断链即回地面（无死亡） |
| **混编** | 3-6 | 四轴同屏 | 每段仍备第二解，无单一最优路线 |

### 3.3 射程工具表（**批量实现的核心校验依据**）

> 基于仓库实测配置纸面推算：`gravity=1800`、`jumpVelocity=-480`、`doubleJumpScale=0.93`、`airJumps=1`、`moveSpeed=140`、`glideMaxFall=140`、`glideActivateVy=60`。满跳+二段跳顶点 ≈ **119px（3.7 格）**；羽降为 140/140 的 **45° 斜降**（水平位移 = 垂直下落距离，1:1）。
> **Δ = 落点相对起点的高度差**，正 = 落点更低（降落式），负 = 落点更高（上升式）。

| Δ（格） | 无羽降·理论 | 无羽降·**关卡安全值** | 羽降·理论 | 羽降·**关卡安全值** | 是否构成「软必需 glide」 |
|---|---|---|---|---|---|
| −2（高 2 格） | 3.3 | **3.0** | 4.0 | **3.0** | ❌ 否（羽降无增益，勿用作教学） |
| −1（高 1 格） | 3.6 | **3.0** | 5.0 | **4.0** | △ 弱（差 1 格，信号不清） |
| **0（同高）** | 3.8 | **3.5** | 6.0 | **5.0** | ✅ 是（差 1.5 格，3-1 S2 已验证） |
| **+1** | 4.0 | **3.5** | 7.0 | **6.0** | ✅✅ 强（差 2.5 格） |
| **+2** | 4.2 | **4.0** | 8.0 | **7.0** | ✅✅✅ 最强（差 3 格，**3-2 主教具**） |
| +3 | 4.4 | **4.0** | 9.0 | **8.0** | ✅✅✅（谨慎用，回程不可逆） |

**由此导出的三条布局规则（全章 5 关通用，写进每份逐关简报）**
1. **必需 glide 的跨越只用 Δ ≥ 0 的降落式**，且 gap 取「羽降安全值」；Δ<0 的上升跨越 **一律 ≤3 格**（羽降对上升零帮助——`activateVy=60` 只在下落段激活）。
2. **任何 gap 不得超过对应 Δ 的羽降安全值**（表中「安全值」列 = 理论 −1 格容错）。超过即为不可过，禁止出现。
3. **主路恒走地面**（ty7,8 全宽 solid）——所有需 glide 的跨越都是 `oneway` 高路，失败落回地面继续前进：**零坠落死亡、零 soft-lock**（2-6 → 3-1 传承的公平地板）。

### 3.4 公平性红线（全章 5 关逐条继承 3-1）

## 7. 机制决策：**Ch3 仅深化 glide，不引入第 2 机制**（推荐）

### 7.1 结论与三条论证

1. **glide 的深度尚未开采完**。§3.2 的四条轴中，3-1 只碰了①的皮毛（同高 5 格）与③的一段（S4 弹幕）；时间轴（②）与链式轴（④）**完全未开采**。在一个机制还有 4 条轴可挖时引入第 2 机制，是**用新鲜感掩盖深度不足**——违反「一个机制吃两层教学」的 3-1 立论。
2. **成本 / 风险不对称**。glide 深化的边际成本 = **0 代码 0 美术**（全部由 tiles 摆位与敌人摆位表达）；任何第 2 机制至少要动 `character-controller` 或接线 `body.ts:90` 的移动平台 stub（3-1 §4.1 已评为「平台跳跃 bug 密度最高的一类」）。Ch3 剩余 5 关是**批量实现**批次，引入引擎变更会让「一批出包」变成「一批返工」。
3. **支柱与动词纪律**。Ch3 的动词是「**浮**」（3-1 §2.1）。第 2 机制必然分走动词焦点 → **支柱漂移**。Ch4 才是引入新动词的正确位置。

### 7.2 若主理人仍要「第 2 机制」——唯一低成本候选（B 方案，默认不启用）

> **不是新机制，是复用已 live 的实体**——因此代码成本为 **0**。

| **建议用法** | 仅 3-5 / 3-6 各 1–2 处，作为三层塔的「电梯」；**不作主路依赖**（主路恒走地面） |
| **代价** | 超出主理人给定的「四敌」约定；需 art-director 补 astral 气柱换皮；且会稀释「Ch3 = 纯 glide 章」的纯度 |
| **默认** | **不启用**。若启用，建议只在 **3-6** 出现 1 处，作为章末的「新鲜感一击」 |

> 明确排除：移动平台（成本中高 + 与节拍平台认知重叠）、重力翻转（手感与可访问性风险）、`bouncy_vine`（与 cyclone 功能重叠，二选一）——理由同 3-1 §4.1。

## 8. 实现批次建议

> 目标：**每批可独立出包验收**，且批内两关共享同一套设计词汇 → QA 一次上下文切换验两关。

| 批次 | 关 | 主题 | 美术依赖 | 工程依赖 | 出包验收重点 |
|---|---|---|---|---|---|
| **批 A** | **3-2 + 3-3** | 空间轴 + 时间轴 | **0** | 0（仅 JSON + LEVEL_ORDER + 测试） | ① §3.3 射程表在真机成立（尤其 Δ=+2 的 7 格长渡）；② glide × 节拍相位窗口是否可稳定命中；③ 双端（Web / 微信）长按手感一致 |
| **批 B** | **3-4 + 3-5** | 代价轴 + 链式轴 | **0** | 0 | ① 弹幕走廊下「不 glide 更安全」是否被玩家读出；② 三层塔（ty5/4/3）在 height=9 下的相机与可读性；③ du_fu 链条断链后的回退体验 |
| **批 C** | **3-6** | climax | 0（A 方案）/ 1 spec（B 方案） | 0（A）/ 3 处极低（B） | ① 密度 0.321 是否越过公平线；② 5 检查点间距；③ par 114000 达标率；④ 破穹之门 payoff 观感 |

**为何是 3 批而非 2 批**：终章是唯一携带**可选美术依赖**与**叙事 payoff**的关，且规模最大（w56 / 18 敌 / 5 cp）。把它与 3-4/3-5 捆在一批，会让美术排期风险传染给两关正常内容关。3 批的代价只是多一次出包，收益是**风险隔离 + 终章可单独打磨**。
> 若主理人坚持 2 批：退化方案 = 批 A（3-2/3-3）+ 批 B（3-4/3-5/3-6），但须**先锁定 §9 拍板项 ②（终章是否新 biome）**，否则批 B 会被美术阻塞。
