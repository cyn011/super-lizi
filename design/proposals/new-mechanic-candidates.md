## 0. 背景与对齐基线

**任务**：用户拍板"增加新关卡"，方向 = **引入新敌种 / 新机制（非纯复用现有 4 敌种）**。

**已读并对齐的现有体系**（GDD01–12、art-bible v1.1、architecture、1-1/1-2 content-spec、level-order）：

# 候选方案 A · 鼓苞（gǔ bāo）— 新敌种（地生喷苞）

## A.1 概念（MDA）
- **动词**：*等 / 读 / 踩*。玩家面对一排会从地面"噗"地弹起的苞，需要在 erupt（弹出）窗口外通过，或在缩回（retract）窗口冒险踩杀。
- **玩家心理（SDT）**：胜任感来自"我读准了它的节奏"；自主感来自"等还是冲"的选择；关联弱（单机）。
- **心流定位**：把"时序压力"做成**可预测的公平节奏**（固定周期，非随机伏击→守"公平失败"支柱），填补现有 4 敌种中**"位置/时间双周期危险"**的空白（ci_li 巡逻、chong_feng 冲锋、du_fu 浮动、shi_pao 开火——均无固定"缩回可踩"窗口）。
- **美学**：Challenge（主）+ Discovery（隐藏节奏）。

## A.2 具体内容（行为规格草案）
- **类型**：新增第 5 敌种 `gu_bao`（地生喷苞）。**不踩管道植物 IP 红线**（它从地面裂缝噗出，无管道）。
- **状态机（表驱动，仿 GDD04）**：
  | 状态 | 行为 | 碰撞/可踩 | 时长（可配 `params.period`） |
  |---|---|---|---|
  | `DORMANT` | 缩于地下，无碰撞、无害 | 无 | `CYCLE_DORMANT=1100ms`（默认） |
  | `EMERGING` | 自地面升起（高 `H=48px`），尖刺顶 | 不可踩（触则 `ON_ENEMY_HIT_PLAYER`） | `EMERGE_MS=160ms` |
  | `ACTIVE` | 完全弹出，尖刺顶危险 | 不可踩 | `ACTIVE_MS=700ms` |
  | `RETRACTING` | 缩回地下，**顶变软** | **可踩**（踩→`ON_STOMP`+100+反弹） | `RETRACT_MS=160ms` |
- **死亡条件**：`RETRACTING` 态被玩家自上方踩中 → `dead` + `ON_ENEMY_DEATH`；其余接触（ACTIVE 顶/侧、EMERGING 顶）→ 玩家受伤（与踩踏互斥，同 GDD04 规则）。
- **公平性**：周期固定、可见前摇（`EMERGING` 起即有视觉/音效预警），避免"看不见致死"（守 art-bible §6.2 可读性）。`params.period` / `params.height` 可实例覆盖，支持"双苞交替"制造节奏走廊。
- **为什么不破坏现有**：纯敌 AI 扩展，不改 form/sizeScale；踩杀复用既有 `ON_STOMP` 经济（+100，无新经济项）。

## A.3 IP 合规
- 命名"鼓苞"= 鼓胀的花苞，自然隐喻，呼应"种子唤醒大地"世界观；**非**任天堂食人花/管道植物（无管道、无大嘴）。
- 剪影：地面裂缝中升起的一枚**带尖刺的膨胀苞**（垂直柱状体），与现有四类（圆刺球/楔形/扁浮/方炮）轮廓全异。
- 配色：**暖橙 `#F2933C`** 苞体（泥土/植物色，避用警示红，因红已被 ci_li/chong_feng 占用）+ **警示红 `#E8483B`** 尖刺顶（危险双编码：尖刺形状 + 红）。不新增色板色。

## A.4 正交性（新逻辑放哪层）
- **`core/enemy`**：`EnemyType` 联合类型**加法**增 `'gu_bao'`；`enemy-ai.ts` 表驱动增 `gu_bao` 的 `state→transition` 映射（纯函数，可单测，零平台）。
- **`game/render/enemy-view.ts`**：程序化占位绘制（MVP 用 Phaser Graphics 画苞体+尖刺，无 PNG）。
- **`game/audio`**：可选新增 `SFX_EMERGE` 占位（**Should**，非 Must；也可复用 `SFX_LAND`）。
- **不触碰**：`core/damage`（sizeScale 不变）、`core/economy`（仅复用 ON_STOMP）、`GDD06 form`、`GDD12` 种子。
- core 仍零 phaser/wx/window；新枚举/状态全部纯数据 + 纯函数。

## A.5 范围分层
- **Must**：`gu_bao` 四态状态机 + 可踩窗口（RETRACTING）+ 1 个使用它的新关卡切片 + 程序化占位渲染。
- **Should**：`SFX_EMERGE` 音频占位；与 `beatPlatforms` 脉冲平台组合段；6 颗种子沿路径触发四阶段。
- **Could**：苞体"喷吐孢籽"装饰粒子（不进经济）；多苞交替节奏走廊强化；变种（更快周期/更大高度）。

## A.6 实现复杂度
- 影响层：`core/enemy`（小）、`game/render`（小）、`audio`（stub 极小）。
- 代码量级别：**小–中**（基本是 GDD04 表驱动模式的加法，无新物理系统）。
- 风险：低。与 shi_pao/ci_li 同属"不可踩危险 / 可踩"二分，复用踩踏判定管线。

## A.7 新关卡内容草案框架
- **建议编号**：`1-3`（草原续章，低风险复用 `grass` 主题程序化资产）；若主理人想换主题亦可 `2-1`（洞穴/天空）。
- **难度定位**：略高于 1-2，但**公平节奏**为主（波浪曲线：教学 1 苞 → 双苞交替走廊 → 组合 4 敌 + beatPlatforms → 检查点 → 终点缓降）。
- **机制组合**：新 `gu_bao` + 现有 4 敌种（可全覆盖或子集）+ 既有 `beatPlatforms`（脉冲平台）+ 6 种子（前 4 触发苗→藤→花→果）+ 2 检查点 + 凯旋之门。
- **程序化资产（MVP 全占位，无 PNG）**：苞体用 Graphics 圆角矩形 + 三角尖刺；沿用现有 `enemy-view` 对象池与 `level` 加载管线。
- **布局草案（非最终 JSON，仅框架）**：`width≈44`，`height=9`，地面 `ty7-8` 全宽；`tx10-12` 单苞教学段；`tx20-26` 双苞交替走廊（params 错相位）；中段混 `ci_li`×2 + `chong_feng`×1 + `du_fu`×1 + `shi_pao`×1 + 1 处 `beatPlatforms`；`tx30` 检查点、`tx38` 检查点；6 种子沿通关路径（藏 1 颗于苞走廊上方需踩杀/二段跳够取）；终点 `triumph_gate`。
- **注册（批准后实施）**：`LEVEL_ORDER` 追加 `'1-3'`（→ `['1-1','1-2','1-3']`），`levels` 记录加 `1-3.json`；`nextLevelId` 纯函数自动续链。

# 候选方案 B · 弹藤跳台（tán téng）— 新机关（弹跳地形）

## B.1 概念（MDA）
- **动词**：*弹 / 叠 / 够*。玩家踩上草藤线圈，被高高弹起，借此越过宽沟、够到高处隐藏种子、或叠二段跳做更长弧线。
- **玩家心理**：胜任感来自"我算准了弹跳落点"；自主感来自"走弹跳线还是绕路"；探索线（隐藏高处种子）满足 Discovery。
- **心流定位**：把"垂直越障"做成**可控的弧线规划**新维度（现有仅靠跳/二段跳，最大 ≈3.6 tile；弹藤显著更高更飘）。
- **美学**：Challenge + Discovery（主）。

## B.2 具体内容（行为规格草案）
- **类型**：新地形/道具机关 `spring_pad`（弹藤跳台）。**非蘑菇弹簧 IP 红线**（线圈草藤，自然隐喻）。
- **触发**：玩家 `v.y>0`（下落）且底接触 pad 顶面 → 设 `v.y = -BOUNCE_PAD`。
  - 建议 `BOUNCE_PAD = -620 px/s` → 弹高 `620²/(2·1800) ≈ 107px ≈ 3.3 tile`，明显高于单跳（≈2 tile）与二段跳（≈1.6 tile），形成"必须用弹藤"的越障。
- **可配 `params.power`**（弱/强两档）；可选 `params.cooldown`（防连弹刷高，默认 0）。
- **正交**：仅改玩家 `v.y`，**不改 form / sizeScale / 经济**；落点可复用 `ON_LAND` 反馈（juice 钩子）。
- **与移动平台组合（Should）**：pad 置于既有 `moving_platform` 上 → 移动弹藤（更高复杂度，见 §B.6）。

## B.3 IP 合规
- 命名"弹藤"= 弹性藤蔓线圈，呼应自然世界观；**非**蘑菇/弹簧高跷等任天堂意象。
- 剪影：地面上一枚**压缩的草藤线圈**（圆盘+卷曲纹），弹起时拉伸。
- 配色：**草绿 `#7CC242`** 藤体 + **暖黄 `#FFD23F`** 高光环（可交互语义，与互动青区分，本物为纯机关非道具）。不新增色板色。

## B.4 正交性（新逻辑放哪层）
- **`core/physics` 或 `core/level`**：pad 作为 `PropDef{type:'spring_pad'}` 或特殊 tile kind；碰撞响应在 `stepBody` 后由关卡/角色层处理（`v.y` 覆写，纯函数）。
- **`game/render`**：程序化占位（Graphics 画线圈 + 压缩/释放 tween）。
- **`audio`**：可选 `SFX_SPRING` 占位（Should）或复用 `SFX_LAND`。
- **不触碰**：form / sizeScale / 经济 / 种子。core 仍零平台。

## B.5 范围分层
- **Must**：`spring_pad` 落地弹起响应 + 1 个使用它的新关卡切片 + 程序化占位。
- **Should**：`SFX_SPRING` 占位；强弱两档 `params.power`；与二段跳叠弧的"秘密种子"设计。
- **Could**：移动弹藤（置于 `moving_platform`）；弹藤连跳挑战段；弹藤 + beatPlatforms 组合。

## B.6 实现复杂度
- 影响层：`core/physics`+`core/level`（中）、`game/render`（小）、`audio`（stub 极小）。
- 代码量级别：**中**（需新增一处碰撞响应分支 + prop 渲染，但无新状态机）。
- 风险：低–中。主要风险是弹跳过强破坏 P1 手感——通过 `BOUNCE_PAD` 集中 config、手感沙盒量化缓降；pad 为可选地形，玩家可绕。

## B.7 新关卡内容草案框架
- **建议编号**：`1-3`（草原）或 `2-1`（天空主题更契合"弹跳/浮岛"）。
- **难度定位**：中，以"垂直越障"为教学新动词；波浪曲线：平地热身 → 首处弹藤教越宽沟 → 弹藤+二段跳够高处种子 → 组合 4 敌 + beatPlatforms → 终点。
- **机制组合**：`spring_pad` + 现有 4 敌 + beatPlatforms + 6 种子（含 1–2 颗仅弹藤/叠跳可够的高处种子）+ 检查点 + 凯旋之门。
- **程序化资产**：pad 用 Graphics 线圈绘制；沿用 level 加载与 render 管线；无 PNG。
- **布局草案**：`width≈44`；`tx14` 第一处弹藤跨越 `tx14-17` 宽沟（宽 3 tile > 二段跳极限）；`tx22` 弹藤上方 `ty3` 藏 1 颗种子（需弹起+二段跳）；中段混敌 + 1 处 beatPlatforms；检查点×2；终点 `triumph_gate`。
- **注册**：同 A.7（追加 `LEVEL_ORDER` + `levels` 记录）。

# 候选方案 C · 翔羽气旋（xiáng yǔ qì xuán）— 新环境机制（上升气流区）

## C.1 概念（MDA）
- **动词**：*乘 / 控 / 离*。玩家进入上升气流柱，被缓缓托起，须主动控横移、择机离场，落到高处平台或越过顶部障碍。
- **玩家心理**：胜任感来自"我在气流里也能稳住"；自主感来自"乘气流还是走地面"；Discovery 来自隐藏高台。
- **心流定位**：引入**持续力场**这一全新压力源（现有物理只有重力+平台；无"反向持续力"），逼迫玩家练习**垂直气控**——全新 mastery。
- **美学**：Challenge + Sensation（轻飘感）。

## C.2 具体内容（行为规格草案）
- **类型**：新环境机制 `updraft`（翔羽气旋），`LevelData` 新增 `zones:[{type:'updraft', x,y,w,h, lift}]`。
- **行为**：玩家 body 与 zone 重叠期间，施加向上加速度 `LIFT`（纯函数，在 `stepBody` 后叠加），并**钳制上升速度** `ZONE_RISE_MAX`（防无限加速）：
  - 建议 `LIFT = 2600 px/s²`（向上）→ 净向上加速度 `2600−1800 = +800 px/s²`；`ZONE_RISE_MAX = 220 px/s`（温和上浮，可控）。
  - 玩家**保留水平控制**（INPUT_LEFT/RIGHT 仍生效）→ 可在气流中横移找出口。
- **正交**：仅改 `v.y` 积分（力场叠加），**不改 form / sizeScale / 经济**；离场后恢复纯重力。
- **Could（非 Must）**：节拍同步气流（脉冲式强弱）——但默认静态，避免与 beatPlatforms 重复且降低风险。

## C.3 IP 合规
- 命名"翔羽气旋"= 卷着落叶/ petals 上升的气旋，自然隐喻；**非**任何任天堂机关。
- 视觉：半透明**天蓝 `#5BC8F5`** 气柱 + **石灰白 `#F4EFE6`** 上升叶片/花瓣粒子（程序化，无 PNG）。
- 配色全在锁色板内（天蓝/石灰白），不新增色。

## C.4 正交性（新逻辑放哪层）
- **`core/physics`**：新增极小的 `applyZones(body, zones, dt)` 纯函数（叠加 `LIFT`、钳 `ZONE_RISE_MAX`），在 `stepBody` 后调用；`core/level` 的 `RuntimeLevel` 暴露 `zones`。
- **`game/render`**：程序化气柱 + 上升粒子（沿用粒子预算 ≤60）。
- **`audio`**：可选环境音占位（Could）。
- **不触碰**：form / sizeScale / 经济 / 种子。core 零平台。
- 注意：`zones` 是 `LevelData` **加法字段**（向后兼容旧关卡，旧关 `zones:[]` 即无效果）。

## C.5 范围分层
- **Must**：`updraft` 力场响应（叠加 LIFT + 钳速）+ 1 个使用它的新关卡切片（竖直升井）+ 程序化占位。
- **Should**：气流中可横移 + 离场落点设计；与 `du_fu`/平台组合；6 种子（含高处藏种）。
- **Could**：节拍同步脉冲气流；多气流接力；气流 + beatPlatforms 组合。

## C.6 实现复杂度
- 影响层：`core/physics`（中，新增力场子系统）、`game/render`（小–中）、`audio`（stub 极小）。
- 代码量级别：**中–大**（力场是相对独立的子系统，需单测覆盖叠加/钳速/离场）。
- 风险：中。持续力场对手感影响最大，须保守调参（`LIFT`/`ZONE_RISE_MAX` 集中 config、手感沙盒量化），且关卡中应设计为**可规避区**（不强制穿越）以守 P1"精准掌控"红线。

## C.7 新关卡内容草案框架
- **建议编号**：`2-1`（**天空主题**最契合"气流/浮岛"，且天然区分于 1-x 草原，降低复用感）。
- **难度定位**：中–高，以"垂直气控"为教学新动词；波浪曲线：首处短气流教上浮 → 气流升井够高台种子 → 气流+平台接力 → 组合 4 敌 + beatPlatforms → 终点。
- **机制组合**：`updraft` + 现有 4 敌（尤其 `du_fu` 空中协同）+ beatPlatforms + 6 种子（含高台/井顶藏种）+ 检查点 + 凯旋之门。

- **注册**：同 A.7（追加 `LEVEL_ORDER` + `levels` 记录；`nextLevelId` 自动续链）。

# 推荐方案

## 推荐：候选方案 A · 鼓苞（新敌种）

**推荐理由（按设计理论红线与工程现实）**：
1. **最贴合任务原话**：用户方向首选项是"新敌种"，A 是货真价实的第 5 敌种，而非复用 4 敌。
2. **架构风险最低**：纯 `core/enemy` 表驱动加法扩展（仿 GDD04），**不引入新物理子系统**，代码量小–中，可单测、零平台、可 headless 仿真——契合 lean 与"core 零平台"铁律。
3. **新增 mastery 最干净**：现有 4 敌种缺"位置/时间双周期 + 缩回可踩窗口"这一维度；鼓苞的"等窗口 / 激进踩杀"是全新决策与压力，且**公平可预测**（固定周期+前摇），守"公平失败"支柱，不引发认知过载。
4. **正交性零侵入**：不改 form / sizeScale / 经济 / 种子；踩杀复用既有 `ON_STOMP`(+100)，无新经济项、无主导策略风险。
5. **内容效率最高**：1 个敌状态机 + 1 个关卡切片即可交付"新关卡"，最快进入可玩验证，符合 lean 节奏。
6. **IP 安全明确**：地生苞、非管道植物；暖橙苞体+红刺的双编码在锁色板内。

**若主理人更想要"新机制"而非"新敌种"**：推荐 **B · 弹藤跳台** 作为机制首选（低风险、垂直越障 mastery 清晰、弹跳参数集中可调、可规避）；**C · 翔羽气旋** 最有新意但风险/代码量最高，建议作为后续章节（2-x 天空主题）的差异化机制，而非首个新关卡。

**组合建议（可选）**：A 与 B 可同关共存（鼓苞时序走廊 + 弹藤越障），互不冲突、正交叠加；但首个新关卡建议**只引入 1 个新元素**以降低认知过载（守支柱检验"不破坏 P1/ P2/ P3"）。

# 需用户拍板的点清单（Decision Checklist）

1. **选哪个候选方案？** A（新敌种·鼓苞）/ B（新机关·弹藤）/ C（新环境·气旋）/ 还是 A+B 组合？

3. **鼓苞（A）是否保留"缩回可踩"奖励窗口？** 推荐**保留**（增加风险/收益 mastery 与 +100 踩杀）；也可简化为纯计时危险（更省实现、更"硬核"）。
4. **弹藤（B）是否需与移动平台组合（移动弹藤）？** 默认**不组合**（Must 仅静态 pad），组合留 Should/Could。
