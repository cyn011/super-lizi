# super-mali 虚拟控件与弹药 HUD 美术规格

> 文档类型：美术规格 / 工程实现合同（给 engineering-lead 直接取数）  
> 上游依据：`art/art-bible.md` v1.1、`design/ux/hud-spec.md`、ADR-004  
> 约束：**零新增位图资源**；所有按钮、图标、HUD 均由 Phaser Graphics 绘制 + 系统字体 + tween 实现。  
> 评审强度：lean

---

## 1. 设计目标

1. **比参考图更好看**：去除参考图里「红方块 + 粗黑描边 +  opaque」的廉价感，改用与栗宝世界一致的圆润、透明、暖色控件。  
2. **不遮挡核心游戏区**：控件集中在屏幕左右下角的「拇指安全区」，中间 60% 区域留给关卡、敌人和栗宝。  
3. **降低误触**：方向键与动作键分开到左右手；同一侧的两个动作键尺寸/位置按频率区分。  
4. **弹药状态可读**：HUD 一眼可见，空弹、拾补、发射都有明确反馈。  
5. **适配微信小游戏移动端**：预留刘海/横条安全区，关键控件可整体内推。

## 5. 方向键：分离式 vs 一体式

**推荐：分离式左/右圆形按钮**（不是十字方向键 / 一体式摇杆）。

理由：

| 维度 | 分离式左/右 | 一体式方向键/摇杆 |
|---|---|---|
| 操作需求 | 横版跳跃只有左右 + 可能的蹲/滑（可跳实现），无上下刚需 | 十字键提供上下，但本作用不上，浪费 30% 区域 |
| 误触率 | 两个独立圆，触点明确，不会误按对角 | 十字中央/对角区容易同时触发左右或误触发上 |
| 拇指尺寸 | 单圆可做到 48–56px 热区，6 寸屏也能单指精确按压 | 十字键四个臂做大了会侵占中间游戏区，做小了难按 |
| 视觉一致性 | 圆润圆形象征栗宝世界的「软、弹」 | 十字/摇杆更像工业控制器，与 IP 温度不搭 |
| 实现复杂度 | Graphics 画两个圆即可，输入状态二元 | 摇杆需要向量计算、死区、归一化，MVP 过度设计 |

> 参考图本身也是左/右两个方块，但我们的分离圆按钮更大、更圆、更透明，且拇指 resting 位置在圆心，不会按到中间分隔条。

## 6. 动作键布局：跳 + 扔如何不挡视线、不误触

### 6.1 布局策略：「主大次小、主低次高」

- **跳跃**是最频繁动作，给 **56×56 大圆**，放在右下角最顺手处（拇指掌根附近）。  
- **扔栗子**是高频但次于跳跃的次要动作，给 **40×40 小圆**，放在跳跃键 **左上方 8px** 处。  
- 这样右手拇指自然下垂时落在跳跃键；拇指指尖上翘即可勾到扔栗子键，形成舒适的「扇形操作区」，无需大幅度移动。

### 6.2 为什么不要「两个等大的并排键」

- 并排会侵占更大的右下角，导致拇指在两个键之间犹豫。  
- 并排的右边缘容易贴近屏幕边框，在小屏上拇指肉垫会误触屏幕外。  
- 一大一小、一低一高，利用拇指不同部位的精确度差异，降低认知负担。

### 6.3 遮挡控制

- 跳跃/扔栗子键均使用 **70–75% 半透明填充**，游戏世界可见。  
- 两个按钮圆心连线的延长线不经过屏幕中心（栗宝通常在中左/中间），不会遮挡角色跳跃弧线。  
- 当栗宝走到屏幕右侧时，控件在角色下方/侧方，不会完全覆盖。

## 7. 弹药 HUD：位置与字号

### 7.1 推荐位置：右上角

- 与左上角 **心形生命** 形成对角平衡。  
- 中上区域留给 **分数 / 排名条**，互不侵占。  
- 右上角离所有虚拟按钮最远，不会在操作时遮挡 HUD。  
- 右手拇指操作时（跳跃/扔栗子），不会同时遮挡右上角。

### 7.2 坐标

- 栗宝图标中心：`(488, 16)`，尺寸 16×16。  
- 数字文本右对齐：`(464, 16)`，字体 14px 系统字体，前缀 `×`。  
- 图标与数字间距 8px。  
- 数字使用 `setOrigin(1, 0.5)` 右对齐，确保弹药从 1 位变 2 位时只向左扩展，不顶到屏幕边缘。

### 7.3 若右上角已有计时/排名条

备选方案（按优先级）：

1. **垂直堆叠**：计时/排名条在上行 `(488, 16)`，弹药 HUD 在下行 `(488, 40)`。两行间距 8px，总高度 40px，仍不挡游戏区。  
2. **水平右排**：从右往左依次是「计时 → 弹药 → 分数」。但会挤压中上空间，不推荐。  
3. **集成到角色头顶**：在栗宝上方画一个小弹药条。优点：与角色强关联；缺点：滚动时会被关卡元素遮挡，且中景 busy 时难读。仅作为未来可选项，MVP 不用。

## 8. 按钮视觉规格

> 颜色全部引用 `art/art-bible.md` §3 色板；描边统一 `#2A1A12`（与 HUD 规格一致）。

### 8.1 基础样式（常态）

| 属性 | 左/右方向键 | 跳跃键 | 扔栗子键 |
|---|---|---|---|
| 形状 | 正圆 | 正圆 | 正圆 |
| 半径 | 24 | 28 | 20 |
| 填充色 | 草绿 `#7CC242` | 天蓝 `#5BC8F5` | 暖橙 `#F2933C` |
| 填充透明度 | 0.75 | 0.75 | 0.75 |
| 描边色 | `#2A1A12` | `#2A1A12` | `#2A1A12` |
| 描边宽 | 2px | 2px | 2px |
| 投影色 | 深绿 `#4A7A29` | 深蓝 `#3A8FBF` | 深橙 `#C06C22` |
| 投影偏移 | `(2, 2)` | `(2, 2)` | `(2, 2)` |
| 投影透明度 | 0.5 | 0.5 | 0.5 |
| 图标色 | 石灰白 `#F4EFE6` | 石灰白 `#F4EFE6` | 石灰白 `#F4EFE6` |
| 图标描边 | `#2A1A12` 1px | `#2A1A12` 1px | `#2A1A12` 1px |

### 8.2 按下态（Pressed）

- **缩放**：整体缩放到 **0.92**（tween 80ms，ease-out）。  
- **填充亮度**：提升约 15%（例如 `#7CC242` → 更亮的 `#9BD85F`），暗示「被点亮」。  
- **描边**：切换为石灰白 `#F4EFE6` 2px，形成内发光 rim。  
- **投影**：偏移减小到 `(0, 1)`，模拟被按下去的物理感。  
- **图标**：图标同步缩放 0.95，保持居中对齐。

### 8.3 高亮态（Hover / 手指刚触碰）

- **缩放**：1.05，150ms tween，ease-out。  
- **发光**：在按钮外缘加 4px 半透明白色描边（`#F4EFE6` alpha 0.4），再衰减。  
- 移动端无 hover，可仅在 `pointerdown` 前一帧或长按 preview 使用。

### 8.4 禁用态（空弹药时扔栗子键）

- **填充色**：去饱和灰 `#8A8A8A`（alpha 0.5）。  
- **图标**：栗宝图标改为灰色，并叠加一个 1px 红色 `#E8483B` 斜叉（×）。  
- **描边**：保持 `#2A1A12` 1px，但透明度降到 0.5。  
- 按下时：按钮不缩放，改为整体 alpha 0.3 闪烁 1 次（0.2s），提示不可使用。

## 9. 图标绘制规格（Phaser Graphics）

> 图标用 Graphics 绘制，不引入位图。所有图标以按钮中心为原点，使用相对坐标。

### 9.1 左/右箭头

- 形式：圆角三角形（chevron），不是细箭头。  
- 尺寸：底边 16px，高 16px。  
- 左键：顶点指向左侧，底边在右。  
- 右键：顶点指向右侧，底边在左。  
- 绘制：使用 `fillTriangle` 或 `path`，然后描边。

```typescript
// 左键示例（中心为原点）
graphics.fillStyle(0xF4EFE6, 1);
graphics.fillTriangle(8, -8, -8, 0, 8, 8);
graphics.lineStyle(1, 0x2A1A12, 1);
graphics.strokeTriangle(8, -8, -8, 0, 8, 8);
```

### 9.2 跳跃图标

- 形式：向上箭头 + 底部一小段弧线（暗示起跳弧线）。  
- 尺寸：箭头高 20px，宽 14px。  
- 颜色：石灰白 `#F4EFE6`。  
- 细节：箭头根部左右各 1px 小芽叶（呼应栗宝头顶嫩芽），使用草绿 `#7CC242` 2px 圆点。

```typescript
// 箭头 shaft + chevron
graphics.lineStyle(3, 0xF4EFE6, 1);
graphics.lineBetween(0, 12, 0, -10);
graphics.lineBetween(-6, -4, 0, -10);
graphics.lineBetween(6, -4, 0, -10);
// 嫩芽
graphics.fillStyle(0x7CC242, 1);
graphics.fillCircle(-3, 10, 2);
graphics.fillCircle(3, 10, 2);
```

### 9.3 扔栗子图标

- 形式：一颗小栗子（圆角椭圆）+ 顶部嫩芽。  
- 尺寸：16×14px。  
- 颜色：主体栗色 `#B5763E`，嫩芽草绿 `#7CC242`。  
- 与栗宝角色一致：圆润、无尖角，强调 IP 识别。

```typescript
graphics.fillStyle(0xB5763E, 1);
graphics.fillEllipse(0, 0, 16, 14);
graphics.lineStyle(1, 0x2A1A12, 1);
graphics.strokeEllipse(0, 0, 16, 14);
graphics.fillStyle(0x7CC242, 1);
graphics.fillCircle(0, -7, 2);
```

### 9.4 弹药 HUD 图标

- 与扔栗子键图标一致，但尺寸 16×16，无描边或 1px 细描边。  
- 常态有轻微呼吸动画（见 §11）。

## 10. 动画反馈

### 10.1 按钮按下反馈

- **缩放 tween**：`scaleX/Y` 从 1 → 0.92，持续 80ms，ease-out；`pointerup` 时回弹 1 → 1.02 → 1.0，持续 150ms，overshoot 轻微弹性。  
- **发光 tween**：按下瞬间外圈 alpha 0.6 → 0，持续 150ms。  
- **投影 tween**：按下时投影偏移 `(2,2)` → `(0,1)`，80ms。  
- 所有 tween 使用对象池或单次 tween，避免每帧 new Tween。

### 10.2 按钮高亮/悬停反馈

- 桌面端 `pointerover`：scale 1.05 + 外圈白色描边 2px alpha 0.4。  
- 移动端可省略 hover，或仅在手指进入热区时触发一次（不持续）。

### 10.3 跳跃键长按提示

- 若长按跳跃键蓄力（如未来多段跳/高跳），在按钮外缘画一个 2px 进度环，颜色 `#FFD23F`（暖黄），顺时针填充。  
- MVP 无蓄力跳，可预留此接口。

### 10.4 扔栗子弹道小像素拖尾

> 属游戏世界 VFX，但由本规格一并定义视觉参数。

- 发射体：栗子形状 8×8px（Graphics 或已有的像素精灵）。  
- 拖尾：发射体每帧生成 1 个 3×3px 小方点，颜色 `#B5763E` → 渐暗到 `#6A4A2E`，life 0.15–0.25s。  
- 数量：同屏最多 5 个拖尾点。  
- 运动：拖尾点继承发射体速度 × 0.6，带轻微向下重力（2px/s²）。  
- 目的：增强「扔出去」的手感，同时不遮挡弹道本身。

## 11. 弹药 HUD 反馈

### 11.1 拾取栗子补给

- **HUD 图标弹跳**：scale 1 → 1.4 → 1.0，持续 0.3s，ease 使用 `Phaser.Math.Easing.Elastic.Out` 或简化的 back-out。  
- **数字弹跳**：文本同步 scale 1 → 1.25 → 1.0，持续 0.2s。  
- **+1 浮字**：在弹药图标上方生成 `+1`（或 `+N`）文本，颜色 `#FFD23F`，向上飘 16px 同时 alpha 1 → 0，持续 0.6s。  
- **可选**：图标外缘 1 次金色闪光环（`#FFD23F` alpha 0.8 → 0，0.2s）。

### 11.2 空弹药提示

- **扔栗子键**：切换为禁用态（§8.4）。  
- **按下空弹键**：按钮 alpha 0.5 → 1.0 闪烁 1 次（0.2s），图标上的红叉同步闪烁。  
- **弹药数字**：数字颜色变为 `#E8483B` 警示红，并闪烁 2 次（周期 0.4s）。  
- **可选弱反馈**：屏幕右侧边缘出现 1 次 4px 红色 pulse（类似心跳），提示弹药不足，不持续。

### 11.3 弹药常态呼吸

- 弹药图标每 2s 做一次轻微 scale 1 → 1.05 → 1 的呼吸，alpha 0.9 → 1.0，让玩家始终意识到弹药系统存在。  
- 空弹药时呼吸停止，改为静态灰态，强化「无弹」感知。

### 11.4 消耗弹药

- 发射时：弹药数字做一个快速「压扁」scaleY 0.8 → 1.0（0.1s），表示减少。  
- 图标同步轻微收缩 0.9 → 1.0（0.1s）。

## 12. 与参考图的对比：为什么更好看/更适合栗宝

| 维度 | 参考图 | 本方案 |
|---|---|---|
| **轮廓形状** | 生硬的矩形圆角，黑粗描边，像贴图 | 正圆 + 统一 2px 细描边，呼应栗宝圆润剪影 |

## 13. 移动端安全区适配（微信小游戏）

### 13.1 问题

微信小游戏在 iPhone 刘海屏、底部横条（Home Indicator）或 Android 水滴屏上，左右/上下边缘可能有一部分不可见或不可触控。本方案不能硬贴边，需要整体内推。

### 13.2 推荐方案：容器级安全偏移

- 所有 HUD + 虚拟控件放入一个 `uiRoot` 容器（`Phaser.GameObjects.Container`）。  
- 基础坐标按 §4 表给出。  
- 启动时读取微信安全区：

```typescript
const info = wx.getSystemInfoSync();
const safe = info.safeArea; // { left, top, right, bottom, width, height }
```

- 计算屏幕物理像素 → 逻辑像素比例：

```typescript
const scaleX = 512 / info.windowWidth;
const scaleY = 288 / info.windowHeight;
```

- 计算逻辑偏移量：

```typescript
const offsetX = Math.max(0, (info.windowWidth - safe.right) * scaleX);
const offsetY = Math.max(0, (info.windowHeight - safe.bottom) * scaleY);
// 也可同时考虑 safe.left / safe.top，取双向最小内推
```

- 将 `uiRoot` 的 `x` 设为 `-offsetX`（或把所有控件容器统一偏移），使按钮离开危险边。  
- 注意：背景/游戏世界不偏移，只偏移 HUD/控件容器。

### 13.3 保守设计

- 即使不做动态安全区读取，基础坐标也已留 20px 边距。在大多数 16:9 设备上可直接使用。  
- 建议预留 `safeOffset` 字段，默认 `(0,0)`；在微信小游戏环境下启用，Web 端保持 0。

### 13.4 刘海/横条具体影响

- **顶部刘海**：主要影响 HUD 上边缘（心形、分数、弹药）。当前 HUD 上边缘 8px，若刘海较大，可由 `uiRoot` 整体下移。  
- **底部横条**：主要影响左右下角按钮。当前按钮下边缘 20px，再由 `uiRoot` 上移，可避开拇指误触 Home Indicator。  
- **左右遮挡**：在极端比例设备上，左右控件可能被黑边裁切；`uiRoot` 整体内推可解决。

## 14. 层级与深度（Depth）

建议沿用 `design/ux/hud-spec.md` §8.3 的 depth 体系，并新增控件层：

| 层级 | depth | 说明 |
|---|---|---|
| 世界图层（地形/敌人/道具） | 0 | 滚动 |
| 栗宝精灵 | 10 | 高于地形 |
| 受伤/无敌覆盖层 | 11 | 跟随栗宝 |
| 抛射物与拖尾 | 12 | 在世界之上 |
| HUD（生命/形态/分数/弹药） | 1000 | `scrollFactor(0)` |
| 虚拟控件 | 1001 | `scrollFactor(0)`，略高于 HUD 避免被 Game Over 遮挡 |
| 暂停/结算面板 | 1500 | 覆盖 HUD 但不覆盖 Game Over |
| Game Over 覆盖层 | 2000 | 最高 |

- 控件容器本身内部无需额外 depth，但图标/阴影/描边建议按 `Graphics` 对象顺序绘制：先阴影 → 再填充 → 再描边 → 再图标。  
- 弹药 HUD 中的 `+1` 浮字 depth 可设为 1100，高于常驻 HUD。

## 15. 实现备注

### 15.1 零位图实现路径

1. **按钮**：用 `scene.add.graphics()` 画圆/阴影/描边；图标也用同一 Graphics 或单独 Graphics。  
2. **数字**：用 `scene.add.text('', { fontFamily: 'sans-serif', fontSize: '14px' })`。  
3. **动画**：用 `scene.tweens.add(...)` 驱动 scale/alpha/offset，不依赖纹理帧。  
4. **输入**：给每个按钮加一个同尺寸透明 `Zone` 或 `Rectangle` 作为热区，监听 `pointerdown`/`pointerup`/`pointerover`/`pointerout`。

### 15.2 性能提示

- 每个按钮的 Graphics 对象在创建时一次性绘制，状态变化时只修改属性（scale/alpha/tint）或重绘简单描边，不要每帧重画。  
- 按钮阴影和图标可合并到同一个 Graphics 中，减少 draw call。  
- 弹药呼吸/弹跳动画通过 tween 驱动，无需每帧更新。  
- 同屏拖尾粒子 ≤ 5 个，对象池复用（见 `art-bible.md` §8 粒子预算）。

### 15.3 与输入系统的接口

美术规格不负责输入逻辑，但控件命名建议如下，方便工程映射：

| 控件 | 建议对象名 | 事件输出 |
|---|---|---|
| 左方向键 | `btnLeft` | `InputAction.LEFT` 按下/抬起 |
| 右方向键 | `btnRight` | `InputAction.RIGHT` 按下/抬起 |
| 跳跃键 | `btnJump` | `InputAction.JUMP` 按下/抬起 |
| 扔栗子键 | `btnThrow` | `InputAction.THROW` 按下/抬起 |
| 弹药 HUD | `hudAmmo` | 监听 `AMMO_CHANGED` / `AMMO_EMPTY` 事件 |

## 16. 可访问性

对齐 `art-bible.md` §9 目标 Standard 级：

1. **热区最小尺寸**：所有虚拟按钮热区 ≥ 48×48 逻辑 px（方向/跳跃均 ≥ 48，跳跃 56）。  
2. **不只靠颜色**：方向键用箭头形状、跳跃用向上箭头、扔栗子用栗子图标，功能不依赖颜色。  
3. **色盲安全**：禁用态扔键额外叠加红色叉号，空弹药闪烁，不靠「颜色变灰」唯一区分。  
4. **减少动态（Reduce Motion）**：开启后，按钮弹跳、弹药呼吸、拖尾粒子全部关闭或替换为静态反馈；无敌闪烁等沿用 `hud-spec.md` 规则。  
5. **光敏安全**：按钮发光/闪烁频率 < 3Hz，单次闪烁 ≤ 0.2s，无全屏高频白闪。  
6. **拇指误触**：按钮之间至少 8px 视觉间隙，热区不重叠；跳跃与扔栗子热区间距 4px（边缘），但中心距足够，实际不会同时触发。
