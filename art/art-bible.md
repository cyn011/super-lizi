## 1. 视觉定位与基调

**一句话定位**
> 一款温暖欢快的原创横版跳跃游戏——让玩家在明亮、手感扎实的像素小世界里，体验纯粹的"跑、跳、踩、顶、吃、抵达"的快乐，全程无任何任天堂 IP 痕迹。

**情绪板（文字描述）**
- **第一感受**：像被阳光晒过的草地，松软、明亮、有弹性。开局即让人放松微笑。
- **温度**：暖。主光来自"午后斜阳"，阴影偏暖紫而非冷黑，避免阴森感。
- **节奏感**：画面元素"圆润、有重量、会回弹"——方块顶起有弹性，角色落地有尘土，敌人被踩会啪叽扁掉。
- **可读性优先**：所有"能互动 / 能吃 / 会咬人"的东西，在 6 寸手机屏上**一眼可辨**：形状先说话，颜色做强化，绝不靠细节堆辨识度。
- **反差**：安全区（草绿、天蓝、暖黄）温柔；危险区（红、橙、尖刺）用高对比与锯齿/尖角语言立刻预警。
- **禁忌情绪**：阴郁、写实血腥、冷峻科幻——均不在本作视觉语言内。
- **参考作品（视觉锚点 §6.4，借结构/手感/可读性，不借美术与 IP）**：Celeste（精准跳跃手感·小屏像素可读·冷暖对比）、Shovel Knight（复古像素的现代打磨·关卡节奏·敌人辨识）、Super Mario Bros.（**仅借**横版卷轴推进节奏与挑战峰布局，**不借任何美术/角色/命名**）、Hollow Knight（仅借氛围质感启发，改用明亮版、不借暗调与角色）、Stardew Valley / Terraria（暖色自然色调·可读像素环境）。

## 2. 美术风格

### 2.1 推荐结论
**采用像素风（Pixel Art）。**（已与视觉锚点 §6.1"现代清晰像素"一致）理由：
1. **最贴合"马里奥式"平台跳跃的手感预期**——玩家对像素跳跃游戏的"重量感/格挡感"已有肌肉记忆，迁移成本最低。
2. **性能友好**：低分辨率位图在 Phaser 3 + 微信小游戏双端几乎零压力，便于在低端机上稳定 60fps。
3. **生产可控**：32px 网格下，单角色约 32–48px，资产量小、迭代快，适合 lean 评审节奏。
4. **跨分辨率稳健**：配合 `pixelArt: true` + 整数缩放，手机小屏不会糊。

### 2.2 备选方案（若主理人否决像素风）
**矢量扁平（Flat Vector）**：用清晰描边 + 平涂色块的原创卡通风。
- 优点：任意分辨率无损、微信多机型显示更一致、UI 与角色风格统一度高。
- 缺点：平台跳跃的"像素手感"需靠动画与音效额外补足；批量生产插画成本略高。
- 若采用，本圣经 §3–§9 的色彩/剪影/可读性规则**全部沿用**，仅替换"网格与描边"为底稿分辨率 2x + 1–2px 外描边。

### 2.3 分辨率与网格规范（关键，需程序对齐）
- **基础内部分辨率**：`512 × 288`（严格 16:9），对应 **32px 瓦片网格 → 横向 16 格 × 纵向 9 格** 满屏。
- **瓦片（tile）基础单元**：`32 × 32 px`。角色与大型道具可跨 1–2 格（32–64px）。
- **细分网格**：大结构按 32px 对齐；角色内部细节允许 16px 半格（如眼睛、手指），但**落点/碰撞盒必须对齐 32px 瓦片网格**。
- **缩放策略**：Phaser `Scale.FIT` + `pixelArt: true` + `roundPixels: true`。在 1920×1080 横屏上接近 ×3.75 缩放并留黑边；优先保证像素不被插值模糊，**禁止 `antialias`**。

### 2.4 描边与抗锯齿策略
- 游戏世界位图：**无抗锯齿**（ nearest-neighbor），`antialias: false`。
- 角色/道具主体：可选 **1px 同色系深色内描边**（silhouette reinforcement），帮助小屏剪影分离；背景层**不使用描边**以保持纵深。
- UI 文字：见 §7（CJK 像素字是生产风险点，单独处理）。

### 2.5 资产命名与导出规范（暂行，待资产清单落地细化）
- 命名：`{类别}_{名称}_{状态/帧}_{序号}.png`
  - 例：`char_mali_idle_01.png`、`env_tile_grass_01.png`、`fx_dust_01.png`、`ui_heart_full.png`
- 格式：角色/道具/瓦片 → **PNG-8 / 索引色（≤ 32 色/图）**；含半透明的特效 → PNG-32。
- 画布：单帧对齐 32 的倍数；序列帧横向排布，配套 `.json` 帧数据。
- 调色板：全项目共用一份 `palette.png`（≤ 64 色），保证跨资产色彩一致。

### 2.6 混合渲染方案（对齐视觉锚点 §6.1）
- **游戏世界（角色 / 敌人 / 地形 / 道具 / 特效）**：像素风，沿用 §2.3–§2.4 的 32px 网格、`pixelArt: true`、无抗锯齿。
- **HUD / 菜单 / 中文标签 / 图标**：采用**矢量扁平或运行时系统字体**（见 §7.1），规避 CJK 像素字库的体积与微信包体风险，保证跨机型文字清晰。
- 两层"质感边界"通过统一圆角、统一描边色与共享调色板弥合，避免 UI 与游戏世界割裂。参考作品对本方案的支撑见 §1 情绪板·参考作品。

## 3. 色彩系统

### 3.1 主色板（暖色主导）
| 角色 | 用途 | Hex | 备注 |
|---|---|---|---|
| 草绿（主） | 地面、草地、安全地形 | `#7CC242` | 明快偏黄绿，避免暗森林绿 |
| 天蓝（主） | 天空、水体、背景 | `#5BC8F5` | 清亮，不与危险红撞色 |
| 暖黄（主） | 阳光、道具高光、强调 | `#FFD23F` | 欢乐感来源 |
| 暖橙（辅） | 泥土、木质、过渡 | `#F2933C` | 与地面绿形成暖调层次 |

### 3.2 功能色（双编码，色盲安全见 §9）
| 功能 | 颜色 | Hex | 形状强化（必带） |
|---|---|---|---|
| 危险/伤害 | 警示红 | `#E8483B` | 尖角 / 锯齿 / 闪烁边 |
| 危险环境反差 | 冷蓝 | `#4A78C0` | 冷调水域/洞穴危险区底色（与增益紫互斥） |
| 奖励/分数 | 金币金 | `#FFC93C` | 圆形 + 中心高光/星点 |
| 可交互 | 互动青 | `#3FC7B4` | 外发光描边 / "✦" 标记 |
| 增益 | 能量紫 | `#9B6CF2` | 果实形 + 顶部嫩芽（**道具专属，不用于敌人**） |
| 生命 | 暖粉红 | `#F26D8B` | 心形（与警示红解耦，见 §6.1 / §9.1） |
| 中立/路径 | 石灰白 | `#F4EFE6` | 平台/路标 |

> ⚠️ **紫色 `#9B6CF2` 专用于增益道具，不用于任何危险/敌人语义**；危险环境反差统一用冷蓝 `#4A78C0`（与 §5.3 洞穴"冷蓝灰"一致）。此分工由视觉锚点 §6.2 冲突修订而来（原锚点"危险用冷蓝/紫"已收敛为冷蓝=危险环境、紫=增益）。

### 3.3 明暗与饱和度策略
- **整体高饱和、高明度**：主体明度 ≥ 60%，饱和度 55–80%，小屏不显灰。
- **阴影用色相偏移而非纯黑**：受光面暖黄，背光面暖紫 `#6E5A8C`，阴影透明度 ≤ 35%。
- **背景降饱和退色**：远景饱和度压到 30–40%、明度 +10%，制造纵深且不与前景抢辨识度。
- **可读性红线**：任意前景元素与相邻背景的**亮度对比 ≥ 3:1**（关键交互 ≥ 4.5:1，参照 WCAG AA）。

## 4. 角色设计语言

### 4.1 通用剪影法则
- **体型对比**：主角"圆而小"，大型敌人"方而大"，飞行敌人"轻而扁"——靠**轮廓体量**先区分。
- **辨识度来源优先级**：① 轮廓剪影 → ② 主色块 → ③ 局部高光/道具 → ④ 细节。小屏下 ① ② 必须成立。
- **色彩编码**：每个角色有**唯一主色 + 唯一轮廓类型**，绝不只靠颜色区分两个角色。

### 4.2 原创主角："栗宝"（Mali）
- **剪影**：矮胖圆润的"栗子精"——整体近似圆角椭圆，身高约 1.25 格（40px），宽约 1 格（32px），重心低、显稳。
- **头部特征**：头顶一枚**嫩绿小芽**（替代任何帽子），芽随跳跃/受击摆动；圆脸、大眼、短腮红。
- **身体**：栗色 `#B5763E` 主体 + 浅色肚皮 `#F0D9B5` + **暖黄 `#FFD23F` 高光**（呼应锚点"暖橙黄主体"、与 §3.1 暖黄一致），无衣裤分化（规避水管工符号）。
- **四肢**：短小圆手圆脚，跑步时呈"风火轮"小弧线；无长四肢。
- **状态可视化**：正常 / 吃到增益（身体泛紫光、体型略胀）/ 受击（红闪 + 缩扁）。
- **绝对禁忌**：红帽、背带裤、胡子、蘑菇头、龟壳——任一出现即视为 IP 风险，驳回。
- **定名**：IP 名"栗宝(Mali)"，呼应项目名 super-mali；锚点原占位"种子精灵"同步更新为此名。

### 4.3 敌人剪影与区分（形状 + 颜色双编码 · MVP 四类）
| 敌人类型 | 轮廓 | 主色 | 行为线索 | 可踩？ |
|---|---|---|---|---|
| 地面慢怪"刺栗" | 圆球 + 周身短刺 | 警示红 `#E8483B` | 左右巡走，刺朝外 | 是（踩顶） |
| **地面冲锋怪"锥冲"** | **长条楔形（前尖后宽）** | 钢蓝 `#3D6FB4` | 直线冲撞、强方向感 | **否（不可正面踩，需闪避/顶）** |
| 飞行"嘟浮" | 扁圆 + 两片小翅 | 蓝紫 `#6E7BF2` | 上下/正弦浮动 | 是（踩顶） |
| 固定炮台"石炮" | 方正石块 + 炮口 | 石灰白+深灰 | 定点发射弹丸 | 否（需绕/顶） |

- **区分原则（MVP 四类）**：刺栗=圆+红+可踩、锥冲=楔形+钢蓝+不可踩、嘟浮=扁+蓝紫+可踩、石炮=方+灰+不可踩——**轮廓四类、颜色四类、行为分两类（可踩/不可踩）**，形状为主、颜色为辅，色盲亦可辨。
- **为何"锥冲"用钢蓝**：它是不可踩的高威胁冲锋怪，归入"冷蓝=危险"语义（见 §3.2 危险环境反差），与可踩的暖红刺栗、蓝紫嘟浮清晰分层；钻地怪归入 Could（后续迭代，见概念 §5）。
- **嘟浮避色**：飞行怪"嘟浮"原为增益紫 `#9B6CF2`，易与增益道具"元气果"混淆，已改为专属蓝紫 `#6E7BF2`；增益紫留予道具独占。

## 5. 环境与关卡美术

### 5.1 图层叠放（由远及近，建议 4–5 层）
1. **天空层**：纯色/缓变渐变（天蓝 `#5BC8F5` → 暖黄底部），可加极简云朵（静态或慢速漂移）。
2. **远景层（parallax 0.3）**：剪影山丘/远景树，降饱和、无描边。
3. **中景层（parallax 0.6）**：灌木、石块装饰，半互动感。
4. **游戏层（parallax 1.0）**：可碰撞地形、砖块、管道替代物、道具、敌人、主角——**全部 32px 网格对齐**。
5. **前景层（parallax 1.2，克制使用）**：偶尔的草叶/藤蔓掠过，增强速度感，但不得遮挡关键路径 >10%。

### 5.2 地形/砖块/管道规范
- **地形块**：草绿顶 + 暖橙泥土身，顶缘 4px 亮草边，明确"可站立"。
- **可顶砖块（"?" 替代为"✦"互动块）**：石灰白底 + 互动青 `#3FC7B4` 外发光 + 中心"✦"标记，明确"可顶出道具"。
- **管道替代物**：原创"藤蔓筒/发光柱"，圆角柱体，避免笔直绿管（去任天堂符号）；用暖色描边区分于背景。

### 5.3 主题切换（色彩与元素差异）
| 主题 | 主色倾向 | 关键元素 | 危险语言 |
|---|---|---|---|
| 草原（教学关） | 草绿 + 天蓝 | 嫩芽、小花、缓坡 | 稀疏刺栗 |
| 洞穴 | 冷蓝灰 + 暖橙火光 | 钟乳、发光晶 | 暗处刺 + 炮台（冷蓝=危险环境反差，见 §3.2） |
| 天空 | 天蓝 + 暖黄云 | 浮岛、风 | 飞行嘟浮密集 |

- 切换时**保留 32px 网格与功能色语义不变**，仅换主色与装饰元素，保证玩家迁移零成本。

## 6. 道具与敌人视觉

### 6.1 道具（形状 + 颜色双编码，确保色盲可辨）
| 道具 | 形状 | 主色 | 功能 | 动效 |
|---|---|---|---|---|
| 爱心（生命） | 心形 | 暖粉红 `#F26D8B` | 回血/加命 | 轻微浮动 + 脉冲光 |
| 金币类（分数） | 圆币 + 中心星点 | 金币金 `#FFC93C` | 计分 | 旋转 + 拾取闪光 |
| 增益"元气果" | 圆果 + 顶部嫩芽 | 能量紫 `#9B6CF2` | 变大/特殊能力 | 吞入膨胀动画 |
| 护盾"壳珠" | 六边形环 | 互动青 `#3FC7B4` | 短暂无敌 | 环绕主角旋转 |

- **严禁**使用蘑菇、星星、火焰花等任天堂经典道具造型；"元气果"以"果实+嫩芽"与马里奥蘑菇明确区分。
- **生命色解耦**：爱心由警示红 `#E8483B` 改为暖粉红 `#F26D8B`，解除"红=危险"与"红=生命"的语义冲突；色盲辅助模式下爱心与危险元素均加白色描边脉冲（见 §9.1）。增益紫 `#9B6CF2` 为道具独占，敌人"嘟浮"已避让（见 §4.3）。

### 6.2 敌人可读性（复用 §4.3 双编码 · MVP 四类）
- 所有敌人在 **最小显示尺寸（约 32px）** 下，仅凭剪影即可判断"能否踩、往哪走"。
- 危险弹丸（石炮发射）：小圆 + 警示红描边 + 拖尾，与背景强对比。

## 7. UI 视觉规范

### 7.1 HUD（顶部常驻，横屏）
- **布局**：左上生命（爱心 ×N 图标），中上分数/金币数，右上计时（倒计时）。
- **风格**：半透明圆角底板（石灰白 60% + 暖描边），不与游戏层抢色。
- **字体**：
  - 数字/英文：**像素字体**（如 `Press Start 2P` 风格自绘位图），基准 8–10px 逻辑尺寸。
  - **中文标签（生产风险提示）**：CJK 像素字库体积大、微信包体受限。**建议**：HUD 尽量用"图标 + 数字"替代中文；必需中文用**圆体无衬线位图字（≥ 12px 逻辑）** 或运行时系统字体叠加，并保证缩放后 ≥ 设计稿 14px 等效。
- **手机适配**：HUD 元素间距按"屏宽 10% 安全边距"布局；按钮热区 ≥ 48×48 逻辑 px（见 §9）。

### 7.2 暂停 / 结算界面
- 暂停：半透明遮罩 + 居中面板，选项用大圆角按钮（开始/继续/重玩），按钮文字 ≥ 14px 等效。
- 结算：过关用"凯旋之门"（原创终点，替代旗杆）动画 + 星级评价（★ 用原创菱形星），失败用温柔提示而非恐吓画面。
- **终点目标物**：原创"凯旋之门 / 回家水晶"，发光拱门，明确"到达即通关"，规避旗杆符号。

## 8. 动效与反馈视觉（Juice）

原则：**每一次操作都给"可看见的回应"**，但克制、不喧宾夺主。

| 反馈场景 | 视觉处理 |
|---|---|
| 起跳 / 落地 | 脚底 3–5 粒尘土粒子（暖橙小点，0.3s 消散）；落地轻微压扁回弹（squash & stretch） |
| 踩怪 | 敌人"啪叽"压扁 + 主角向上小弹弧；爆出 4–6 粒同色碎屑 |
| 吃道具 | 道具缩放弹出（punch）+ 中心闪光环（0.2s）+ 主角短暂高光 |
| 受击 | 全屏 0.15s 红闪（半透明叠加，**非全白高频闪**）+ 主角击退 + 无敌闪烁 1.5s |
| 顶互动块 | 块上顶 4px 回弹 + "✦"弹出道具 + 小星光 |
| 通关 | 凯旋之门亮起 + 主角跃入 + 星雨粒子（慢速、低对比，避免密集闪光） |

- **粒子预算**（lean）：同屏粒子 ≤ 60 粒；单粒子贴图 ≤ 8×8px；用对象池复用。
- **屏幕震动**：仅受击/落地重击触发，幅度 ≤ 4px、时长 ≤ 0.2s，且可在设置中关闭（见 §9）。

## 9. 可访问性

### 9.1 色盲安全
- **绝不只用颜色传递关键信息**：所有功能色（危险红 / 危险环境冷蓝 / 奖励金 / 互动青 / 增益紫 / 生命粉红）**必须搭配形状或图标**（见 §3.2、§6）。
- 主色板已避开"红—绿"唯一对比：危险用红+尖角、危险环境用冷蓝、奖励用金+圆、互动用青+发光、增益用紫+果实、生命用粉红+心形，六者色相跨度大、形状各异。
- **生命色解耦**：爱心改用暖粉红 `#F26D8B` 而非警示红，避免"红=危险"与"红=生命"冲突；紫色 `#9B6CF2` 仅用于增益道具，敌人已避让。
- 提供 **"色盲辅助模式"**：开启后危险元素与爱心均加白色描边脉冲，进一步剥离颜色依赖。

### 9.2 最小可点 / 可辨尺寸
- **游戏内可交互物体**：≥ 1 格（32px 逻辑），缩放后等效 ≥ 约 48 设备 px，手机一眼可辨。
- **UI 按钮热区**：≥ 48×48 逻辑 px（参照移动端最小触控目标）；视觉图标可更小但热区不小于此。
- **文字**：中文等效 ≥ 14px、数字/英文像素字 ≥ 10px 逻辑，缩放后清晰。

### 9.3 动态模糊 / 闪烁的克制
- **防光敏癫痫**：全屏闪烁频率 **< 3Hz**，单次日闪 ≤ 0.2s、不连续超过 1s；受击红闪用半透明叠加而非高频白闪。
- **减少动态（Reduce Motion）开关**：设置中提供，开启后关闭屏幕震动、粒子密度减半、通关星雨改为静态。
- **视差与动态模糊**：前景 parallax 速度差 ≤ 0.3，避免强动态模糊导致晕动；眩晕敏感玩家可关前景层。

### 9.4 可访问性分级（建议）
本作目标达到 **Standard** 级（色盲双编码 + 最小尺寸 + 减少动态开关 + 按钮热区达标）；若工期允许冲刺 **Comprehensive**（增加色盲辅助模式脉冲、字幕/提示强化）。UX 规格须引用此分级。
