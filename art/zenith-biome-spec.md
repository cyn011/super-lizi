## 0. 范围与锁色板（红线基准）

本 biome 仅负责**破晓穹顶（zenith）主题视觉**、**四类通用敌的 zenith 换皮与破晓逆光可读性专项（A5）**、**破穹之门 `triumph_gate` 视觉变体（A6）**；玩法 / 数值 / 物理（glide 钳制、射程表、投掷、碰撞、可踩语义）由 chapter-3-plan 与工程负责，**本 biome 仅提供视觉规格，不改任何机制语义、不写代码**。

> ### ⚠️ 关键美术决策一（设计意图 · 提请主理人知悉）
> **zenith 的手法是「明度再翻面」，与 2-6 volcano 的「色温翻面」是同一套 art-bible 语言的不同维度。**
>
> | 章 | 终章 | 手法 | 从 → 到 |
> |---|---|---|---|
> | Ch2 | 2-6 volcano | **色温翻面** | 冷寂深渊（cave 冷蓝）→ 炽热引爆（熔金炽红） |
> | Ch3 | **3-6 zenith** | **明度再翻面** | 墨色星穹（astral：天暗地亮）→ 破晓天光（zenith：**天亮地暗**） |
>
> astral 是全 biome 唯一「地比天亮」（`bg #1F2244` L≈0.019 / `rockFace #BEC4F9` L≈0.573，对比 ≈10:1）。
> **zenith 把这组关系整个对调**：`bg #FFE695` L≈0.800 / `rockFace #373D79` L≈0.055，对比 **≈8.1:1**，方向相反。
> 叙事读法（对齐 chapter-3-plan §2.5）：**「同一片星岩，天亮了」**——栗宝撞裂穹壳，光从上方涌入；星白浮岩转为**逆光暗剪影**，墨色星空转为**破晓金天**。3-5《凌霄绝息》段末「那不是天，那是一层壳」的伏笔，在这里由**画面本身**作答。
>
> ### ⚠️ 关键美术决策二（光照模型 · 决定全部下游规则）
> **zenith = 全项目第一个「逆光 / rim-light」biome。** 光源在**上方穹壳裂口**，所有实体逆光：
> - **地形**：暗体（`rockFace`）+ **亮顶缘**（`crystalGlow #FFD23F`）——可站立信号回到 **volcano 的「亮顶缘」范式**，而非 astral 的「暗顶缘」。
>   **这是被数据逼出来的，不是风格偏好**：zenith 下 `rockFace #373D79` vs `rockBody #1F2244` 仅 **1.54:1**、vs `outline #2A1A12` 仅 **1.68:1**——astral 的暗边方案在 zenith **物理上不可读**。必须有一个亮槽承担顶缘（`#FFD23F` vs 岩面 **6.9:1** ✅）。
> - **敌人**：暗体 + 2px 描边 + 1px 破晓亮 rim（详见 **A5**）。
> - **冷暖分工（zenith 的视觉论点）**：**暖 = 新世界的光**（金天 / 顶缘金边 / 云海橙缘 / 暖尘）；**冷 = 旧星界的余烬**（`#5BC8F5` 破穹之门核心 / 残余星辉 / ghost 边）。玩家看到的是「暖光正在吃掉冷光」——这就是「终启」。

> **读表规则（zenith 的核心可读性纪律）**：`bg` 极亮、`rockFace` 极暗 → **暖亮槽（`crystalGlow`/`crystalCore`/`firelight`）只在「暗岩前景」承担分离职责，绝不在天空前独立承担**；**天空前的分离一律交给 `outline` `#2A1A12`（13.56:1）与暗体**。凡在天空前出现的亮元素（门核 / 光柱 / 暖尘），必须**带 `outline` 描边或走 alpha 装饰层**，不得作为需要一眼定位的关键交互物的唯一识别手段。此规则是 A5 与 A6 的共同前提。

> **8 字段名与 `ASTRAL`（`theme-palette.ts:267-276`）逐字一致**，工程仅需新增一个 entry，无接口变更。8 个权威 hex 中 3 个为 tint 派生（`#FFE695` / `#373D79` / `#1F2244`），其余 5 个直取锁色板，**无任何新 hex**。
>
> **撞色审查（同 volcano §7 / astral §1.2 纪律）**：暖黄 `#FFD23F` 从未被任何 biome 占为 `bg`（volcano/astral 皆作点缀）→ zenith 取其高明度 tint 作天空，是**锁色板内最后一个未被占用的天空明度×色温象限**（亮·暖天 + 暗地，见 §6.3 审计）；蓝紫 `#6E7BF2` 被 storm_sky 占为中明度地面主面、被 astral 占为暗面 → zenith 用其 **darken 0.5 暗 tint** 作地面，三者明度带完全错开。✅

## 2. 瓦片调色板规则（复用 base 集 + runtime tint · 破晓游戏层）

- **复用 1 份 base 瓦片集**，结构/功能语义不变（`ground_top` / `ground_fill` / `oneway` / `interactive_block`）；zenith 经 theme palette 映射（§1.2）生成，**不另绘瓦片集**（守 ADR-004）。
- **功能语义不变**：solid / oneway / 可踩判定与全部前序 biome 一致；仅主色由星白 `#BEC4F9` 翻为深星紫 `#373D79`。

### 2.1 solid（地面 / 浮岩）—— 逆光暗剪影 + 破晓亮顶缘

- **Tier-1（现状即成立，0 绘制分支）**：通用分支 `fillRect(rockFace #373D79)` + `1px outline #2A1A12`（`game-scene.ts:1910-1913`）。在破晓金天前，整块地形以 **8.06:1** 的暗剪影成立——**zenith 是唯一一个「不做任何新绘制分支也能读对」的暗地面 biome**（volcano 的黑岩在暗紫天前仅 3.5:1，astral 的亮岩靠 tint 差）。
- **Tier-2（推荐，1 处绘制分支）· 顶缘破晓亮边**：solid 顶面绘 **1–2px 破晓金 `#FFD23F`（`crystalGlow`）+ 内 1px 晨曦暖橙 `#F2933C`（`firelight`）**——即 **volcano 亮顶缘范式的同构复用**（volcano 是 `#F2933C` 外 + `#FFD23F` 内，zenith 对调冷暖顺序以表达「更高更亮的光」）。顶缘 vs 岩面 **6.90:1** ✅，远超关键交互 4.5:1。
  > ⚠️ **不得沿用 astral 的暗顶缘**：`rockBody`/`outline` 对 `rockFace` 分别仅 1.54:1 / 1.68:1，暗边在 zenith 不可见。此项若不排期，Tier-1 的「无顶缘」状态仍可玩（地形整体剪影成立），但**逐块可站立信号丢失**，在 3-6 的三层塔（ty5/4/3）密集堆叠区读感会下降 → 建议排期。
- **浮岩剪影（形状语言，无新色）**：沿用 astral 的**倒棱台**离散浮岩（底面收窄），底缘叠深空影 `#101A2A` 渐隐——**同一形状语言、相反明度**，玩家迁移零成本。
- **云海地面（ty7,8 全宽 solid）**：深星紫面 + 顶缘破晓金边 + 表面 2–3 道 **晨曦暖橙 `#F2933C` 云缘横带**（astral 是冷调 `#BDE9FB` 云纹 → zenith 是**被朝阳染红的同一片云海**，deco 换皮，碰撞语义不变、不挖坑）。这是「天亮了」最直接的一处游戏层证据。

### 2.2 oneway（浮岛高路 / 长渡落点）

- **Tier-1（现状即成立）**：通用分支 `fillRect(rockBody #1F2244, 顶半)` + `1px outline`（`game-scene.ts:1929-1932`）。vs 破晓金天 **12.41:1** —— **全 biome 最强的 oneway 剪影**，3-6 的长渡落点岛在天空中一眼可辨。
- **Tier-2**：顶缘 1px `#FFD23F` 破晓边（区分「可站立」）+ 底缘 `#101A2A` 收窄倒棱台（区分「悬空」）；与 solid 的差异靠 **半格高度 + 更暗的体色**（`#1F2244` vs `#373D79`，1.54:1 属**有意的弱差**——oneway 更暗 = 「更薄、更悬」）。

### 2.3 beatPlatforms（节拍平台）· 视觉与渲染红线

> **⚠️ 关卡侧红线（chapter-3-plan §4.3 / §8.2-3）：3-6 的两簇节拍平台 `bp_z1`（S2 段）/ `bp_z2`（S4 段）瓦片必须位于 `ty=4`（y=128），严禁 `ty=5`；全章上限 2 簇，不得超。**

- **ghost 态（未实体化）**：**2px `#1F2244` 虚描边框（alpha 0.9）+ 内部 `#373D79` alpha 0.25 填充**。
  > ⚠️ **不得沿用 astral 的「半透亮体 + 星辉边」**：astral 的 ghost 是「半透星白 + `#5BC8F5` 微光边」，靠亮体在墨天上成立；zenith 的天是亮的，**半透暗体会被天空冲淡**（alpha 0.35 的 `#373D79` 叠在 `#FFE695` 上等效 L≈0.54，vs 天仅 1.44:1）。故 ghost 态改由**暗虚框**承担（框 vs 天 **12.41:1** ✅），形状语言 = 「框 = 还没长出来的岩」。
- **实体态**：满不透明 `#373D79` + 顶缘 `#FFD23F` 破晓亮边（同 solid）。
- **状态双编码**：ghost → 实体 = **虚框 → 实心 + 亮顶缘**（形状 + 明度双变化，不依赖色相；色盲安全）。

## A5 · 破晓逆光敌人可读性专项（重要 · 本 biome 独有问题）

> ### ⚠️ 方法论说明（提请主理人知悉：手法复用 volcano，但**反差方向按实测背景重定向**）
>
> 任务书要求「复用 volcano 的暗底亮敌手法」。我按仓库实测核算后，**保留 volcano 的方法论（用明度反差 + rim 保证剪影），但把反差方向调转**，理由是硬数据：
>
> **zenith 下敌人的主要背景是天空，不是地面。** 四敌 y 契约为 `gu_bao=224` / `ci_li=200` / `du_fu=120` / `shi_pao=100`，而地面顶面在 ty7（y=224）——**四类敌的可见体块 100% 位于地面线之上，背景即 `bg` 破晓金天（L≈0.80）**。故：
> - volcano（暗天 `#3F45A8` L≈0.15 + 黑地）→ 敌人需**亮**元素；
> - **zenith（亮天 `#FFE695` L≈0.80 + 暗地）→ 敌人需暗体**；
> - 但 3-6 有**三层浮岩塔（ty5/4/3）**与长渡浮岛，du_fu（y=120）/ shi_pao（y=100）会周期性掠过 `rockFace #373D79` 暗岩前景 → **暗体在暗岩前又会糊**。
>
> **故 zenith 必须双向安全：暗体（对亮天）+ 亮 rim（对暗岩）。** 这正是 volcano「靠一道亮边把实体从同色背景里拉出来」手法的直接移植，只是从「平台顶缘」移植到「敌人上缘」。

**总原则（三管齐下，全部锁内色）**：① **体色压暗**——地面三敌主体取 `#373D79`（对亮天 8.06:1）；② **上缘 1px 破晓金 rim `#FFD23F`**——逆光轮廓光（对暗岩 6.90:1），同时是全 biome 统一的「光从上方来」的物理表达；③ **描边加强**——亮天前出现的敌体一律 **2px `#2A1A12`**（较全局 1px 加倍，vs 天 13.56:1）。**形状 + 明度双编码，不依赖色相，色盲安全（WCAG ≥3:1，关键交互 ≥4.5:1）。**

### A5.3 判定规则（给渲染占位与后续真美术的统一口径）

1. **敌体/关键交互物在亮天（`bg`）前景出现时**（zenith 的绝大多数情况）：主体明度须落在「暗带」（等效 luminance ≤0.10，即 `#373D79` / `#1F2244` / `#2A1A12` 档），且描边一律 **2px `#2A1A12`**，保证剪影 ≥4.5:1。
2. **敌体在暗岩（`rockFace` / 三层塔 / 云海地面）前景出现时**：上缘绘 **1px `#FFD23F` 破晓 rim**（6.90:1），必要时外缘再加 1px `#F2933C` 暖软边（等效「逆光轮廓光」，与 volcano 亮发光边同源）。
3. **亮天前禁用中—高明度冷亮色作独立识别手段**：`#5BC8F5`（1.54:1）、`#FFD23F`（1.17:1）、`#F2933C`（1.89:1）、`#F2C94C`（1.29:1）、`#BEC4F9`（1.37:1）在 `#FFE695` 前**全部低于 3:1**——它们只能用于**暗岩前景**、或**必须带 `#2A1A12` 描边**、或作为 alpha ≤0.22 的氛围叠层。**这是 zenith 最容易被违反的一条，列为渲染评审必检项。**
4. **危险部位永远红 + 尖角**，可踩窗口永远暖黄 + 发光环——功能色语义全局不变（art-bible §3.2），本专项只动「底色适配」，不动语义色。
5. **色盲自检口径**：以上全部依赖**明度差 + 形状**而非色相差（deuteranopia / protanopia / tritanopia 下明度关系不变），Standard 档达标。

### A5.4 `cyclone` 上升气流在 zenith 下的可读性口径

> **问题来源（design-strategist 在 `design/gdd/level-3-6-design.md` 附录 B·R5 指出）**：3-6 首次把 `cyclone`（上升气流柱）放进 zenith 场景；`src/game/render/cyclone-view.ts` 的占位主色为 `#5BC8F5`（crystalCore 青），而本 biome 天空是破晓金天 `#FFE695`——按 A5.3 规则 3 同一口径，气柱在亮天里近乎不可见。3-6 仅 1 处 cyclone（tx43-45，三层塔顶 `T3` 的保底解 + gauntlet 重试站），**不阻断出包**，但会严重削弱其**可发现性**（玩家看不见「电梯」就想不到去用）。

#### A5.4.1 问题量化（现状占位实测）

| 元素 | 占位主色 | vs 破晓金天 `#FFE695` | 判定 |
|---|---|---|---|
| `cyclone` 主柱（青） | `#5BC8F5` | **1.54:1** | ❌ 低于 3:1，亮天前实质隐形（与 A6.2 门芯同值，但门有 2px 描边兜底，气柱当前仅 1px 半透描边） |
| `cyclone` 漩涡辉光（蓝紫） | `#6E7BF2` | **≈2.95:1** | ❌ 临界、仍偏弱（暗天成立，亮天失效） |
| `cyclone` 升腾粒子（暖黄） | `#FFD23F` | **1.17:1** | ❌ 比青更糟（与 §1.2 `crystalGlow` 同值） |

> 1.54:1 来由与 A5.3 / A6.2 完全一致（`#5BC8F5` L≈0.501 vs `#FFE695` L≈0.800 → (0.800+0.05)/(0.501+0.05)=1.54:1）。**根因**：`cyclone-view.ts` 与 `enemy-view.ts` 同源——占位**不消费 palette / 不读 theme**，把 storm_sky 暗天下的青柱原样搬进亮天即失效。三种占位色在亮天前**全部低于 3:1**，整根气柱等于隐形。

#### A5.4.2 推荐方案（全部锁内色 / tint，0 新增 hex）

气柱是**关键交互物（玩家要「看见电梯才用得上」）**，故遵循 A5.3 规则 3「亮天前关键元素必须带 `#2A1A12` 描边」纪律，把气柱做成一道**逆光暗管**：

| 部件 | 处理（锁内 / tint） | 角色 / 对比（见 A5.4.3） |
|---|---|---|
| **暗管填充** | `rockBody #1F2244` alpha ≤0.5（穹壳暗面 tint，0 新增） | 给气柱一个暗底，使内部粒子有对比依托；半透 → 读成「被晨光罩住的上升气流」而非实心地形 |
| **暗管描边** | **2px `#2A1A12`**（outline，满 alpha） | 气柱 silhouette 对金天 **13.56:1** ✅——**可发现性的硬兜底**，无论内部粒子是否可见，柱形一眼可辨 |
| **升腾粒子** | **`#F2933C`（晨曦暖橙，firelight）** | 暖 = 新世界的光托你上升（对齐 §0 冷暖分工）；vs 暗管 **6.57:1** |
| **中心旋纹线** | `#5BC8F5`（残星辉青，crystalCore） | 保留气柱跨 biome 身份（与 storm_sky 同青芯）；vs 暗管 **8.03:1** ✅ |
| （可选）次旋纹 | `#6E7BF2`（蓝紫） | 落在暗管内 vs `#1F2244` **4.21:1**，作次级装饰，不承载识别 |

> **对设计简报建议（「+2px `#2A1A12` 描边 + 粒子改 `#F2933C`」）的采纳与修正**：采纳描边 + 暖粒子的方向；**补充一道 `#1F2244` 半透暗管填充**——因为暖粒子 `#F2933C` 对裸金天仅 1.89:1（仍不可见），必须落在暗底上才成立（6.57:1）。若无暗管，单加描边 + 暖粒子，粒子仍「描在金天里」；且现状粒子是 `#FFD23F`（1.17:1）比简报假设的更糟，改 `#F2933C` 是必要而非可选。中心旋纹保留青色以维持气柱辨识连续性。

#### A5.4.3 对比比复核（改后各元素）

| 元素 | 对比基准 | 对比比 | 判定 |
|---|---|---|---|
| 暗管描边 `#2A1A12` | vs 破晓金天 `#FFE695` | **13.56:1** | ✅（silhouette 成立，与 §1.2 outline 同值） |
| 暗管填充 `#1F2244` | vs 破晓金天 `#FFE695` | **12.41:1** | ✅（柱体成形，与 §1.2 rockBody 同值） |
| 升腾粒子 `#F2933C` | vs 暗管 `#1F2244` | **6.57:1** | ✅（≥ 关键交互 4.5:1） |
| 中心旋纹 `#5BC8F5` | vs 暗管 `#1F2244` | **8.03:1** | ✅（身份保留） |
| （最差情形）升腾粒子 `#F2933C` | vs 裸金天 `#FFE695`（粒子逸出管外边角） | 1.89:1 ⚠️ | 由「粒子严格限在暗管内 + 暗管 silhouette 13.56:1」兜底，不依赖粒子裸天对比 |

> **结论**：气柱的**可发现性由暗管 silhouette（描边 13.56:1 + 填充 12.41:1）保证**，与粒子裸天对比无关；粒子与旋纹在暗管内均 ≥6.5:1，**达标**。所有数值与 A5.3 / §1.2 同口径（WCAG 相对亮度法），无任何新 hex。

#### A5.4.4 Tier 分级

- **判定：Tier-2（建议排期，不阻断出包）**——依 design-strategist R5 明确结论：3-6 仅 1 处 cyclone、为保底解非唯一通路，出包不依赖此项。
- **但属「高优先级 Tier-2」**：它是 `T3` 塔顶保底解 + gauntlet 重试站，关系到关键路径的**可发现性**。若不做，降级体验为：气柱在亮金天里近乎隐形（主柱 1.54:1 / 粒子 1.17:1），玩家**看不见「电梯」就想不到去用**——机制本身仍可工作（踩中即被托起），但会因「找不到」而卡关重试、或放弃保底解走更难路线，挫败感显著。建议与 A5.2 敌人换皮一并排期（同属「占位未随 biome 重着色」欠账，可一次清）。

#### A5.4.5 实现落点（给 engineering-lead 的契约）

- **文件**：`src/game/render/cyclone-view.ts`（与 `enemy-view.ts` 同源的占位渲染；当前 `drawCyclone(g, e)` 无 theme 参数，全 biome 同渲）。
- **改动量**：约 **12–18 行**——为 `drawCyclone` 增 theme 入参（或读 `level.metadata.theme`），新增 `theme === 'zenith'` 分支与一组 zenith 专用常量（`#2A1A12` / `#1F2244` / `#F2933C` / `#5BC8F5`，**全部已在 11 色板内，无需新增全局 palette 字段**）；非 zenith 分支原样保留现有 `#5BC8F5` 主柱 + 1px 半透描边 + `#FFD23F` 粒子的 storm_sky 观感。
- **⚠️ 硬约束：按 biome 分支，禁止全局改动。**
  - **采用「按 biome 分支」**：`cyclone-view.ts` 据 theme 分流——`zenith` 走新暗管口径，`storm_sky`（及任何非 zenith）**原样保留现有渲染**。
  - **否决「全局安全的加法」**：若给所有 cyclone 统一加描边 / 暗管，会**直接改写 2-3 storm_sky 已 live 的 4 个 cyclone 实例观感**（见 `src/config/levels/2-3.json:70/76/81/90`），违反「任何改动不得让 2-3 的现有观感回归」红线。故 zenith 口径必须**隔离在 biome 分支内**。
  - **回归风险评估**：按 biome 分支实现 → storm_sky 的 4 个 cyclone **零改动、零回归**（代码路径不进入 zenith 分支）；新颜色均复用既有锁色板项，**不触碰 storm_sky 的 palette 注册**，无连带影响。
- **可访问性（沿用 §7 / §3.2）**：升腾粒子为连续流（非脉动），仍须 `Reduce Motion` 下**冻结首帧**（静态暗管 + 暂停粒子，silhouette 仍 13.56:1 可发现）；暗管为局部管状（非全屏）明度变化，不触发「亮基底禁止全屏明度脉动」红线；配色全锁内、色盲靠明暗 + 形状双编码。

## A6 · 破穹之门（`triumph_gate`）视觉变体

> 对齐 chapter-3-plan §4.1 / §4.2：`triumph_gate` 同一实体、**两种视觉语义**——2-6「**出渊之门**」= 离开旧世界；3-6「**破穹之门**」= 穿透新世界的边界。**语义反转必须落在形状上，不能只靠换色。**

### A6.1 设计意图

**出渊之门是被「造」出来的（规整晶体拱门）；破穹之门是被「撞」开的（不规则纵向裂口）。** 门不是终点建筑，是**壳上的那道缝**——玩家看见的不是「一扇门」，而是「穹顶裂开的地方」。这是 3-6 叙事 payoff（「外面不是终点，是又一片更远的天」）在美术上的落点，也与远景 `deco_dawn_rift`（§2.5）构成**远景预告 → 近景兑现**的呼应。

### A6.2 Tier-1（0 绘制分支，现状即成立）

通用分支 `fillRect(crystalCore #5BC8F5)` + `2px outline #2A1A12`（`game-scene.ts:1941-1944`）。
- 门芯 `#5BC8F5` vs 破晓金天 **1.54:1** ⚠️ ——**但成立**，因为：① **2px `#2A1A12` 描边 vs 天 13.56:1**（形状完全清晰）；② 门体下半通常贴 `rockFace` 暗地形，门芯 vs 暗岩 **5.23:1** ✅；③ 青 vs 金是锁色板内**唯一的近互补色对**（色相跨度最大），主观辨识远好于明度数字；④ 凯旋之门位置固定在关末、玩家已在 14 关中习得语义。
- **判定：Tier-1 可接受，不阻断出包**；但作为章末唯一 payoff，**建议排 Tier-2**。

### A6.3 Tier-2 破穹之门变体（推荐 · Graphics，锁内色 0 新增）

## 6. 与 astral / silhouette / desert 的差异清单（**缩略图尺度防混淆** · chapter-3-plan §6.3 风险 R 应答）

> chapter-3-plan §6.3 明确列出风险：「与 silhouette（亮天+暗地）在**缩略图尺度**下可能贴近，需 art-director 复核」。本节为该复核结论。
> **自检口径（供 QA / 主理人验收）**：把关卡首屏截图缩到 **32×18 px**（内部分辨率的 1/16）并去除全部细节，只剩天空与地形两个色块；两个 biome 必须在该尺度下一眼分辨。

### 6.1 与 astral 的差异（**结论：不可能混淆**）

| 维度 | astral（3-1~3-5） | **zenith（3-6）** | 缩略图可辨性 |
|---|---|---|---|
| **天空 `bg`** | `#1F2244` 墨蓝（L≈0.019，**全 biome 最暗天**） | `#FFE695` 破晓金（L≈0.800，**全 biome 最亮天**） | **明度极值两端**，43× 亮度比 |
| **地面 `rockFace`** | `#BEC4F9` 星白（L≈0.573，**唯一亮地面**） | `#373D79` 深星紫（L≈0.055） | 10× 亮度比 |

> **玩家读法**：3-5 结束 → 3-6 开场，画面从「深色底 + 亮岩」瞬间翻成「亮色底 + 暗岩」。这不是「换了个 biome」，是**同一个世界被点亮了**——正是 §4.2 要求的「章末视觉事件」。✅

### 6.2 与 silhouette（2-4 剪影回廊）的差异（**结论：可辨，但需守两条纪律**）

二者结构确实同类：**亮天 + 暗地**。逐项核算：

| 维度 | silhouette（2-4） | **zenith（3-6）** | 差距 |
|---|---|---|---|
| 天空 `bg` | `#5BC8F5`（L≈0.501，**冷青**，H≈197°） | `#FFE695`（L≈0.800，**暖金**，H≈47°） | **明度 1.60× + 色相 150° 对立 + 冷暖相反** ✅ |
| 地面 `rockFace` | `#254060`（L≈0.049，蓝，H≈207°） | `#373D79`（L≈0.055，紫，H≈235°） | 明度几乎相同、色相仅差 28° ⚠️ |
| 天地对比 | 5.57:1 | **8.06:1** | 1.45× |
| 暗面 `rockBody` | `#1C2E49` | `#1F2244` | **近乎不可分** ⚠️ |

**结论：地面完全不承担分辨职责，分辨全部压在天空上。** 天空的 150° 色相跨度 + 1.6× 明度差在 32×18 px 下**足以一眼分辨**（冷青天 vs 暖金天是人眼最敏感的色温判断）。为把余量做厚，追加两条纪律：

- **纪律 A（0 成本，构图承担）**：**zenith 的天空占比须 ≥55%**，地形为**离散悬空块 + 大面积留白**；silhouette 是**连绵廊柱竖直密排、贯通画面**。3-6 的 tiles 布局（长渡星隙 / 三层塔 / 窄岛）天然满足，**无需任何额外工作**，但须写进 3-6 逐关简报作为构图约束。
- **纪律 B（Tier-2，形状承担）**：`deco_dawn_rift` **穹壳裂口**为 zenith 独有的远景剪影元素——画面上方一道压入式弧带 + 纵向裂缝，silhouette 完全没有对应形状。此为**决定性差异**，建议与 Tier-2 顶缘亮边一并排期。

## 10. 与 chapter-3-plan §6.3 的对齐与**偏离说明**

> 本规格 8 槽中 **6 槽逐值采纳** chapter-3-plan §6.3 的建议表，**2 槽偏离**。逐条说明如下，**偏离项需主理人确认**。

| 槽 | plan §6.3 建议 | 本规格 | 结论 |
|---|---|---|---|
| `bg` | `#FFE695` | `#FFE695` | ✅ 照单采纳（含「刻意区别于 desert `#F7BE8A`」的意图，§6.3 已核算） |
| `rockFace` | `#373D79` | `#373D79` | ✅ 照单采纳 |
| `rockBody` | `#1F2244` | `#1F2244` | ✅ 照单采纳（「astral 天空色降级为地面暗面」的设计意图完整保留） |
| `outline` | `#2A1A12` | `#2A1A12` | ✅ |
| `danger` | `#E8483B` | `#E8483B` | ✅ |
| `crystalCore` | `#5BC8F5` | `#5BC8F5` | ✅ 采纳（破穹之门核心 / 残星） |
| **`crystalGlow`** | `#5BC8F5` | **`#FFD23F`** | ⚠️ **偏离** |
| **`firelight`** | `#FFD23F` | **`#F2933C`** | ⚠️ **偏离** |

**偏离理由（两槽为一组，不可拆）**

1. **功能必要性**：zenith 地面是暗面 → 可站立信号必须由**亮槽**承担（astral 的暗顶缘在 zenith 仅 1.54–1.68:1，物理不可读）。`crystalGlow` 是 volcano 既定的「顶缘亮边主色」槽位，故由它承担 `#FFD23F`（vs 岩面 6.90:1）最符合既有工程语义，`drawTerrain` 的亮顶缘分支可与 volcano 共用同一段代码。
2. **表现必要性**：若 `crystalGlow` 与 `crystalCore` 同为 `#5BC8F5`（原案），则 8 槽中唯一的暖亮色只剩 `firelight`，**游戏层将没有任何暖元素**——「破晓」只发生在背景天空，玩家操作的那一层仍是「冷紫岩 + 青辉」，读起来像「astral 换了个天」而非「天亮了」。把暖光下放到顶缘 / 云缘 / 暖尘，破晓才落到玩法层。由此确立 zenith 的冷暖分工：**暖 = 新世界的光，冷 = 旧星界的余烬**。
3. **`firelight` 无副作用**：仓库中 `pal.firelight` 的通用消费点仅 `drawMountainLantern`（mountain 专用，`game-scene.ts:2140`），种子 / 金币走 `seed-view` / `coin-view` 的硬编码色 —— 改值对 zenith 之外**零影响**。
