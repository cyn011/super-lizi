# ADR-004 · 资源加载与包体策略

- **状态**：Accepted（包体预算为硬约束，策略据此定）
- **日期**：2026-07-21
- **作者**：程基岩（engineering-lead）

## 背景
微信小游戏硬性限制：**主包 4MB、整包 8MB**。像素资产体积小天然友好，但音乐/音效/图集/代码仍可能超限。需明确加载与打包策略，确保主包达标且 MVP 可运行。

## 决策
1. **图集打包**：所有像素精灵（角色/敌人/地形/道具/UI 图标）打包为 **1 个 atlas**（PNG-8 索引色 ≤64 色、32px 网格对齐、nearest-neighbor），由图集工具产出 Phaser 兼容 JSON。
2. **音频-音乐：远程流式**：MVP 音乐走 **CDN/远程 URL**（`wx.createInnerAudioContext().src` / Web `Audio()`），**不进主包**。
3. **音频-SFX：合成占位**：MVP 建议用 **WebAudio 振荡器合成短音**（零音频文件进包），或极短占位音；资产就绪后替换。彻底规避音频包体风险，且天然满足"音频占位不崩"（GDD 09）。
4. **关卡数据**：MVP 主关随包（JSON 极小）；后续关卡走**微信子包（subpackage）**，计入 8MB 而非主包。
5. **字体**：HUD/中文走**运行时系统字体**（矢量），不进包；数字像素字可选自绘小位图。规避 CJK 像素字库包体风险（美术圣经 §7.1）。
6. **代码**：Vite `build` 开启 `minify` + `tree-shaking` + 按需引入 Phaser 模块；`import.meta.env` 按平台裁剪。

### 主包预算（控制基线，详见 control-list §2）
| 项 | 预算 | 备注 |
|---|---|---|
| 业务+引擎 JS（min） | ≤1.5MB | tree-shaking；Phaser 按需 |
| 图集 atlas（PNG-8） | ≤1.0MB | 单图集；超则拆分仍主包内 |
| config + 主关 JSON | ≤100KB | 极小 |
| SFX 合成（可选文件） | ≤100KB | 若不用合成则 0 |
| **主包合计** | **≤2.7MB（留 ~1.3MB 余量）** | 远低于 4MB 红线 |
| 整包（含子包/远程音频） | ≤8MB | 音乐走远程不计入 |

## 备选
- **音乐随包**：MVP 即内嵌音乐 → 主包极易爆 4MB；否决。
- **CJK 像素字库**：包体风险高、微信受限；否决（采用系统字体，见上）。
- **多图集分散**：单图集更省管理、省 draw call；除非单图集超 1MB 再拆。

## 后果
- 正面：主包安全余量大、加载快、音频零包体、后续内容靠子包扩展不破上限。
- 负面/风险：音乐依赖远程 URL（需 CDN/网络）；离线首玩可能无声（占位可接受）；图集工具链需纳入构建脚本。
- 已确认（2026-07-21 主理人拍板）：图集工具选型 **`free-tex-packer`**（开源 CLI，零成本，输出 Phaser 兼容 atlas JSON），纳入 Vite 构建脚本。付费备选 `TexturePacker` 不采用。
