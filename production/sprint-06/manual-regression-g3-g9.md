## 1. §4 ③ 触屏按钮热区 ≥48px（微信）

**步骤**
- [ ] 打开 `src/config/input-config.json` 的 `wechat.buttons`，按逻辑分辨率高 512 折算：每个按钮命中区直径 `2*r*512/设计高 ≥ 48px`。
- [ ] 真机/模拟器逐一**点按四钮中心与四角**（各偏移 ±24px），确认均触发对应动作（走/跳/暂停/重玩）。
- [ ] 确认相邻按钮热区间**无重叠误触**。

**判定**：四钮均可点中且有效热区 ≥48×48 → PASS；任一不达标 → FAIL（回 engineering-lead 调 `input-config.wechat.buttons`）。

---

## 2. §4 ⑤ 平台切换不丢输入（onHide/onShow）

**步骤（微信）**
- [ ] 游戏中触发 `wx.onHide`（切后台/锁屏/切到聊天）→ 仿真应冻结（等同暂停），不崩、不丢输入状态。
- [ ] 回前台 `wx.onShow` → 仿真恢复，输入连续：按住方向/跳的手势不丢、不卡死、不重复触发。
- [ ] 连续多次切后台/回前台，无累积延迟、无输入串台。

**步骤（Web）**
- [ ] 浏览器切标签页/窗口失焦 → 等价暂停；回焦点恢复，输入连续。

**判定**：切后台冻结 + 回前台无缝恢复、输入不丢 → PASS；丢输入/卡死/重复 → FAIL（回 S05-5 lifecycle 钩子）。

## 3. §4 ⑦ 音频首次交互解锁

**步骤（微信）**
- [ ] 进入后**首次** `touchstart`/`click` → 其后 `playSfx` 调用不崩、无 "AudioContext 未解锁" 类红错。
- [ ] 踩敌/吃币/跳/通关分别触发对应 SFX（WebAudio 合成，零文件），无异常。
- [ ] 远程 music URL 流式加载（**不进包**，见 G4 包体核对）。

**步骤（Web）**
- [ ] 首次 `click` 解锁 `AudioContext`；之后 SFX 正常。

**判定**：首次交互后音频可用、无红错 → PASS；解锁失败/红错 → FAIL（回 S05-4 `audio-bus`）。

## 4. §4 ⑧ 存储双端一致（存档/解锁/星/最佳时间）

**步骤（Web）**
- [ ] 通关后 `localStorage` 写入：解锁下一关 + 星 + 最佳时间；刷新页面后读取保持。

**步骤（微信模拟器/真机）**
- [ ] 通关后 `wx.setStorageSync` 写入一致；重进读取保持；与 Web 语义对齐（同 `StoragePort` 接口）。
- [ ] 多关解锁态正确累积，不丢档。

**判定**：双端读写一致、持久化正确 → PASS；任一端丢失/错乱 → FAIL（回 S05-3 `SaveManager`）。

## 5. S05-2 新增手测（暂停 / 结算 / 重试）— G1·V4 闭环收尾

- [ ] 双指暂停（或专用键 / 微信 `onHide`）→ 暂停遮罩 + 「继续」「重玩」按钮（热区 ≥48×48，中文 ≥14px）。
- [ ] 仿真冻结、输入不丢；「继续」无缝恢复。
- [ ] 抵达凯旋之门 → 结算屏 + 星级（时间维度 50% + 金币收集率 50%）；「再玩一次」重开本关。
- [ ] 失败（命耗尽）→ 温柔「再试一次」。

**判定**：暂停 + 结算 + 重试全流程通过 → V4 闭环 ✅（关闭 G1 最后一块，见门报告 G1）。
